# Реестр критических ошибок

> **Назначение:** Хранилище критических ошибок, которые приводили к нарушению целостности конфигурации/ИБ.  
> **Цель:** Не допускать повторения этих ошибок при разработке.  
> **Правило:** При КАЖДОМ нарушении целостности — агент ОБЯЗАН записать ошибку сюда ПЕРЕД продолжением работы.

---

## Формат записи

```text
### [YYYY-MM-DD] Краткое описание ошибки

- **Категория:** XML | BSL | Деплой | Структура | Данные
- **Симптом:** Что произошло (ошибка в логе, потеря данных, etc.)
- **Причина:** Корневая причина проблемы
- **Решение:** Как была исправлена ошибка
- **Правило-предохранитель:** Что теперь ОБЯЗАТЕЛЬНО делать/НЕ делать, чтобы ошибка не повторилась
- **Затронутые файлы:** Список файлов, которые были повреждены/исправлены
```

### [2026-03-10] Double BOM в XML файлах, создаваемых через create_file

- **Категория:** XML / Деплой
- **Симптом:** LoadConfigFromFiles падает с "Document is empty" на позиции [1,1] для Template.xml отчёта ДвижениеТоваров
- **Причина:** Инструмент `create_file` VS Code Copilot вставляет BOM (ef bb bf) автоматически. Если содержимое файла уже начинается с BOM (от агента-кодера), получается двойной BOM (ef bb bf ef bb bf). XML-парсер 1С не может прочитать такой файл
- **Решение:** Проверить hex первых байтов файла. Если `ef bb bf ef bb bf` — удалить лишний BOM. Использовать Python-скрипт: `data = path.read_bytes(); if data[:6] == b'\xef\xbb\xbf\xef\xbb\xbf': path.write_bytes(b'\xef\xbb\xbf' + data[6:])`
- **Правило-предохранитель:** После создания XML-файлов через `create_file` — ОБЯЗАТЕЛЬНО проверить hex первых байтов на Double BOM. Если агент-кодер генерирует содержимое с `<?xml` — убедиться что BOM не дублируется
- **Затронутые файлы:** `Reports/ДвижениеТоваров/Templates/ОсновнаяСхемаКомпоновкиДанных/Ext/Template.xml`

### [2026-03-10] Предупреждение LoadConfigFromFiles "Неверное имя команды элемента формы"

- **Категория:** XML / Деплой
- **Симптом:** LoadConfigFromFiles возвращает exit code 1 с предупреждением "Неверное имя команды элемента формы. - Form.Command.X". Конфигурация при этом ЗАГРУЖАЕТСЯ успешно — это предупреждение, не блокирующая ошибка
- **Причина:** Форма обработки ВыручкаЗаСмену создана агентом вручную (без Конфигуратора). Платформа генерирует предупреждение, но загрузка проходит
- **Решение:** Игнорировать при exit code 1. Проверить через CheckConfig — если прошёл, конфигурация загружена. Продолжать с UpdateDBCfg
- **Правило-предохранитель:** Exit code 1 от LoadConfigFromFiles НЕ обязательно означает сбой. ВСЕГДА проверять через CheckConfig. Если CheckConfig проходит — конфигурация загружена, можно обновлять БД
- **Затронутые файлы:** `DataProcessors/ВыручкаЗаСмену/Forms/Форма/Ext/Form.xml`

### [2026-02-24] ИБ повреждена после UpdateDBCfg — "Ошибка формата потока"

- **Категория:** Деплой / Данные
- **Симптом:** После успешного деплоя (LoadConfig + CheckConfig + UpdateDBCfg) все последующие обращения к ИБ через Designer падают с "Ошибка формата потока". Это затрагивает CheckConfig, LoadConfigFromFiles, и любое открытие Designer. Новые бэкапы тоже содержат повреждённый конфиг.
- **Причина:** UpdateDBCfg сохранил конфигурацию в ИБ в состоянии, которое Designer не может прочитать. Точная причина неизвестна (возможно несовместимость объектов внешней библиотеки БПО). Все бэкапы, созданные ПОСЛЕ первого удачного UpdateDBCfg, содержат повреждённый конфиг.
- **Решение:** Восстановить ИБ из `1Cv8.dt` (бэкап ДО появления проблемы). Затем повторить полный деплой — всё проходит успешно.
- **Правило-предохранитель:** При "Ошибка формата потока" в ANY операции Designer — сначала проверить состояние ИБ через CheckConfig. Если тоже "Ошибка формата потока" — ИБ повреждена. Нужен откат к СТАРОМУ .dt (до первого повредившего UpdateDBCfg). Все бэкапы .dt ПОСЛЕ того деплоя тоже повреждены. Использовать `1Cv8.dt` из корня проекта (стабильный) или более ранний backup.
- **Затронутые файлы:** `D:\Confiq\Public Trade Module\1Cv8.1CD` (ИБ), восстановлена из `1Cv8.dt`

### [2026-02-19] Код Номенклатуры ДОЛЖЕН быть строковым (CodeType=String)

- **Категория:** Структура
- **Симптом:** При открытии РМК крашилась панель товаров: `Несоответствие типов (параметр номер '1')` в `Команды.Добавить(ИмяКоманды)` — строка 1249 Module.bsl
- **Причина:** `CodeType` справочника Номенклатура был изменён с `String` на `Number`. Код использовался в `СтрЗаменить()` для формирования имён команд панели товаров РМК, но числовой тип не поддерживается `СтрЗаменить()` без явного приведения к строке
- **Решение:** Возвращён `CodeType=String` в `Catalogs/Номенклатура.xml` (обе папки)
- **Правило-предохранитель:** НИКОГДА не менять `CodeType` справочника Номенклатура на `Number`. Код используется как строка в панели товаров РМК (`ОбновитьОтображениеНоменклатурыНаСервере`) для формирования имён команд и кнопок. Любое изменение типа кода ломает РМК
- **Затронутые файлы:** `Catalogs/Номенклатура.xml`, `DataProcessors/РабочееМестоКассира/Forms/Форма/Ext/Form/Module.bsl`

### [2026-02-16] Изменения BSL не применяются — папка Проверка не обновлена

- **Категория:** Деплой
- **Симптом:** После деплоя поле ДокументРасчетов в регистре Взаиморасчеты оставалось пустым при проведении документов, хотя код был правильно изменён
- **Причина:** BSL-модули были обновлены ТОЛЬКО в `Конфигурация/Documents/...`, но НЕ в `Конфигурация/Проверка/Documents/...`. Deploy-config.ps1 загружает конфигурацию из папки `Проверка`, поэтому старый код без изменений попал в ИБ
- **Решение:** Применить те же изменения BSL/XML ко ВСЕМ копиям в обеих папках: `Конфигурация/` и `Конфигурация/Проверка/`
- **Правило-предохранитель:** При редактировании ЛЮБОГО файла (BSL, XML) — ОБЯЗАТЕЛЬНО вносить изменения в ОБЕ папки: `Конфигурация/` И `Конфигурация/Проверка/`. Деплой загружает ТОЛЬКО из Проверка. Изменения только в Конфигурация/ НЕ попадут в ИБ
- **Затронутые файлы:** `Конфигурация/Проверка/Documents/ПриходТовара/Ext/ObjectModule.bsl`, `Конфигурация/Проверка/Documents/РасходныйКассовыйОрдер/Ext/ObjectModule.bsl`

### [2026-02-13] Команда формы без Action — кнопка не видна на клиенте

- **Категория:** XML
- **Симптом:** Кнопка, привязанная к команде формы, отображается в Конфигураторе, но НЕ видна в клиенте 1С
- **Причина:** В определении `<Command>` в Form.xml отсутствует элемент `<Action>ИмяПроцедуры</Action>`. Без него платформа не связывает команду с BSL-обработчиком и не показывает кнопку на клиенте
- **Решение:** Добавить `<Action>ИмяПроцедуры</Action>` в каждый `<Command>` в Form.xml. Имя должно совпадать с именем процедуры `&НаКлиенте` в Module.bsl
- **Правило-предохранитель:** При создании Command в Form.xml — ОБЯЗАТЕЛЬНО добавлять `<Action>`. Минимальная структура команды: `<Command name="..." id="N"><Title>...</Title><ToolTip>...</ToolTip><Action>ИмяПроцедуры</Action></Command>`. НЕ добавлять Use, Representation, ModifiesStoredData, CurrentRowUse — они необязательны и могут вызвать проблемы
- **Затронутые файлы:** `Documents/РасходныйКассовыйОрдер/Forms/ФормаДокумента/Ext/Form.xml`
