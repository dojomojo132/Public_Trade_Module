# План синхронизации данных между Базовым ПК и Кассой через HTTP API

> **Дата:** 2026-02-24
> **Архитектура:** 2 ПК с идентичной конфигурацией PTM, файловые ИБ
> **Связь:** Локальная сеть, HTTP API через Apache

---

## Общая схема

```
┌─────────────────────┐         HTTP API          ┌─────────────────────┐
│    ОСНОВНАЯ БД      │◄────────────────────────►│      КАССА           │
│  (сервер, Apache)   │                           │  (РМК, продажи)     │
│                     │                           │                     │
│  Справочники:       │   GET /api/search         │  РМК:               │
│  - Номенклатура     │◄─────────────────────────│  - Поиск товара      │
│  - Цены             │   JSON: товар + цена      │    по штрихкоду      │
│  - Штрихкоды        │                           │                     │
│                     │   POST /api/check         │  При закрытии чека:  │
│  Приём чеков:       │◄─────────────────────────│  - Отправка данных   │
│  - Создание ЧекККМ  │   JSON: товары + оплата   │    чека в осн БД     │
│  - Проведение       │                           │                     │
│  - Движения по РН   │   POST /api/goods/sync    │  Обновление товаров: │
│                     │──────────────────────────►│  - Синхронизация      │
│                     │   JSON: массив товаров    │    справочника       │
└─────────────────────┘                           └─────────────────────┘
```

## Этапы реализации

### ЭТАП 1: API на основной БД — Поиск товара (УЖЕ ГОТОВ ✅)
- **Endpoint:** `GET /api/search?code=<штрихкод_или_код>`
- **Результат:** JSON с данными товара, ценой, штрихкодами
- **Статус:** Работает, протестировано

### ЭТАП 2: API на основной БД — Обновление товаров (синхронизация)
- **Endpoint:** `POST /api/goods/sync`
- **Тело запроса:** JSON с параметрами фильтрации (дата последнего обновления)
- **Ответ:** JSON-массив ВСЕХ товаров с ценами и штрихкодами
- **Назначение:** Касса вызывает для обновления локального справочника Номенклатура
- **Логика на основной БД:**
  1. Выбрать все элементы `Справочник.Номенклатура` (не удалённые)
  2. Для каждого — получить розничную цену и штрихкоды
  3. Вернуть массив JSON
- **Логика на кассе (клиентская сторона):**
  1. Вызвать API
  2. Для каждого товара: найти/создать в Номенклатура, обновить цены в РС.ЦеныНоменклатуры, обновить штрихкоды в РС.Штрихкоды
- **Тест:** Запросить синхронизацию → проверить что все товары и цены приходят

### ЭТАП 3: API на основной БД — Приём чека (продажа с кассы)
- **Endpoint:** `POST /api/check`
- **Тело запроса (JSON):**
  ```json
  {
    "date": "2026-02-24T15:30:00",
    "cashRegister": "Касса1",
    "warehouse": "Основной склад",
    "items": [
      {
        "code": "000000725",
        "quantity": 2,
        "price": 1132,
        "amount": 2264,
        "discountAmount": 0,
        "barcode": "725"
      }
    ],
    "payments": [
      {
        "type": "Наличные",
        "amount": 2264
      }
    ],
    "totalAmount": 2264,
    "discountCard": "",
    "status": "Пробит"
  }
  ```
- **Логика на основной БД:**
  1. Создать документ `ЧекККМ`
  2. Заполнить шапку: КассоваяСмена (найти/создать), Касса, Склад, СуммаДокумента
  3. Заполнить ТЧ Товары: найти Номенклатуру по коду, заполнить Количество, Цена, Сумма
  4. Заполнить ТЧ Оплата: ВидОплаты, Сумма
  5. Провести документ → движения по регистрам ОстаткиТоваров, Продажи, ДенежныеСредства
  6. Вернуть JSON: `{success: true, number: "ЧК-000001", ref: "uuid"}`
- **Тест:** Отправить чек → проверить что ЧекККМ создан и проведён → движения в регистрах

### ЭТАП 4: Модификация РМК на кассе — Вызов API при продаже
- **Где:** Обработка `РабочееМестоКассира`, модуль формы
- **Что менять:**
  1. При пробитии товара — вместо локального `НайтиТовар()` вызвать HTTP-запрос к основной БД
  2. При закрытии чека — отправить данные чека по API в основную БД
  3. Добавить настройку URL основной БД (параметры сессии или константа)
- **Важно:** РМК на кассе должен работать и без связи (fallback на локальные данные)

## Новые методы HTTP-сервиса

### URLTemplate: /goods/sync (ЭТАП 2)
| Метод | Handler | Описание |
|-------|---------|----------|
| GET | `СинхронизацияТоваровGET` | Вернуть все товары с ценами и ШК |

### URLTemplate: /check (ЭТАП 3)
| Метод | Handler | Описание |
|-------|---------|----------|
| POST | `ПриёмЧекаPOST` | Принять чек с кассы, создать и провести ЧекККМ |

## Технические ограничения

1. **Файловая ИБ:** Одновременный доступ ограничен. Apache блокирует ИБ при запросах.
2. **VRD авторизация:** Пользователь `Админ` без пароля прописан в VRD.
3. **Кодировка:** JSON ответы в UTF-8. Кириллица в полях работает.
4. **Конфликт /PTM:** Используем RootURL `api` (не `ptm/api`). URL: `/ptm/hs/api/...`
5. **HTTP-сервис на кассе:** Кассе НЕ нужен свой HTTP-сервис (она клиент). Нужен общий модуль для HTTP-вызовов к основной БД.
