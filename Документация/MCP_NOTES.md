## Cat C: Инструменты

### import_data
Массовый импорт элементов справочников/документов из JSON.

**Параметры:**
- `metaType` (обяз.) — `Catalogs` или `Documents`
- `name` (обяз.) — имя объекта метаданных (напр. `Склады`, `ПриходТовара`)
- `data` (обяз.) — JSON-строка с массивом объектов
- `updateExisting` (опц., default: `false`) — обновлять существующие

**Формат данных:**
```json
// Для справочников:
[{"description": "Имя элемента", "attributes": {"Реквизит": "Значение"}}]

// Для документов:
[{"attributes": {"Склад": "Основной склад"}, 
  "tabularSections": {"Товары": [{"Номенклатура": "Товар 1", "Количество": 5}]}}]
```

**ВАЖНЫЕ МОМЕНТЫ:**
1. **Поиск по наименованию**: существующие элементы ищутся по `Наименование` (справочники) или `Номер` (документы)
2. **Дубликаты**: если `updateExisting=false` и элемент существует — создаётся ДУБЛИКАТ (не пропускается!)
3. **Ссылочные реквизиты**: значения ищутся по `Наименование` — передавать строковое наименование, а не ссылку
4. **Пустой массив**: корректно обрабатывается (возвращает "0 записей")
5. **Ошибки**: невалидный JSON, несуществующий тип/объект — все выдают isError=true с описанием
6. **Табличные части**: работают через ключ `tabularSections` с вложенными массивами


### clear_deleted
Поиск и удаление объектов, помеченных на удаление.

**Параметры:**
- `metaType` (опц.) — фильтр: `Catalogs`, `Documents` или пропустить для всех
- `dryRun` (опц., default: `true`) — только показать, НЕ удалять

**ВАЖНЫЕ МОМЕНТЫ:**
1. **По умолчанию безопасный**: `dryRun=true` — только отображает помеченные, не удаляет
2. **Проверка ссылок**: перед удалением проверяет ссылочную целостность через `НайтиПоСсылкам`
3. **Табличный вывод**: показывает Markdown-таблицу с объектами, связями и возможностью удаления
4. **Фильтрация**: `metaType='Catalogs'` или `'Documents'` — ищет только в указанном типе
5. **Реальное удаление**: `dryRun=false` — удаляет только те, у которых нет ссылок. С ссылками — пропускает


### get_data_history
История изменений объекта через Журнал регистрации.

**Параметры:**
- `metaType` (обяз.) — `Catalogs`, `Documents`
- `name` (обяз.) — имя объекта (напр. `Склады`, `ПриходТовара`)
- `searchValue` (опц.) — наименование/номер конкретного элемента
- `lastMinutes` (опц., default: 1440) — период в минутах (1440 = 24 часа)
- `maxRows` (опц., default: 50) — лимит строк

**ВАЖНЫЕ МОМЕНТЫ:**
1. **Источник данных**: ЖурналРегистрации (Журнал регистрации 1С)
2. **Фильтрация**: по типу метаданных, конкретному элементу (через `searchValue`), периоду
3. **Пустой результат**: при lastMinutes=1 может вернуть 0 записей — это нормально
4. **maxRows работает**: ограничивает количество возвращаемых строк
5. **Формат**: Markdown-таблица с колонками: Дата, Событие, Пользователь, Комментарий
6. **Несуществующий объект**: корректная ошибка "не найден"

## Cat D: Ресурсы

### ptm://registers
Подробная карта ВСЕХ регистров конфигурации.

**Содержимое (~9600 символов):**
- Регистры накопления (5): ОстаткиТоваров, Взаиморасчеты, ДенежныеСредства, Продажи, ЗаказыКлиентов
- Регистры сведений: Цены, НастройкиСканеров и др.
- Для каждого: Измерения (с типами), Ресурсы (с типами), Реквизиты, Регистраторы

**Когда использовать:** 
- Перед написанием запросов к регистрам — посмотреть доступные измерения/ресурсы
- Для понимания связей "документ → какие регистры двигает"


### ptm://business-logic
Карта документооборота конфигурации.

**Содержимое (~8600 символов):**
- Все документы: КассоваяСмена, ЧекККМ, ПриходТовара, СписаниеТовара и др.
- Для каждого: реквизиты (с типами), табличные части (с колонками), движения (в какие регистры)
- Списки отчётов и обработок

**Когда использовать:**
- Перед созданием формы документа — посмотреть реквизиты и ТЧ
- Для анализа бизнес-логики "документ → регистры → отчёты"

## Cat D: Промпты

### generate_report_module
Шаблон модуля отчёта.

**Аргументы:**
- `reportName` (обяз.) — имя отчёта (должен существовать в метаданных!)
- `mode` (опц.) — `СКД` (по умолчанию) или `Программный`

**Что возвращает (~4100 символов для СКД):**
- Метаданные отчёта (имя, синоним, реквизиты)
- Список ВСЕХ регистров с измерениями и ресурсами
- Требования к генерации (СКД: набор данных/поля/группировки; Программный: макет/запрос)
- Стандарты BSL

**ВАЖНО:** Если reportName не существует — ВызватьИсключение со списком доступных отчётов


### generate_form_handlers
Шаблон обработчиков формы объекта.

**Аргументы:**
- `metaType` (обяз.) — `Catalogs`, `Documents`, `DataProcessors`, `Reports`
- `objectName` (обяз.) — имя объекта

**Что возвращает (~1200-1400 символов):**
- Реквизиты объекта с типами
- Табличные части с колонками
- Список обязательных обработчиков: ПриСозданииНаСервере, ПриОткрытии
- Обработчики для реквизитов-ссылок: ПриИзменении
- Обработчики для ТЧ: ПриНачалеРедактирования, ПриОкончанииРедактирования, ПослеУдаления
- Стандарты BSL (директивы, области, асинхронность)


### diagnose_data_integrity
План расследования нарушения целостности данных.

**Аргументы:**
- `registerName` (опц.) — имя регистра (если указан — включает метаданные регистра)
- `symptom` (опц.) — описание проблемы

**Что возвращает (~1300 символов):**
- Симптом (если указан)
- Метаданные регистра: измерения, ресурсы, регистраторы (если указан registerName)
- 6-шаговый план с MCP-инструментами:
  1. `get_register_data` → проверка текущих остатков
  2. `get_register_data` mode=All → анализ всех движений
  3. `get_document_movements` → проверка документов-регистраторов
  4. `get_object_module` → аудит кода проведения
  5. `get_data_history` → отслеживание изменений
  6. `post_document` + `compare_periods` → перепроведение и сравнение

**ВАЖНО:** Несуществующий registerName НЕ вызывает ошибку — просто план без метаданных регистра

## Общие замечания для агента

1. **42 инструмента + 4 ресурса + 6 промптов** — полный набор MCP-сервера PTM
2. **Ссылочные реквизиты**: при создании/импорте элементов ссылочные реквизиты ищутся по Наименованию
3. **dryRun по умолчанию**: clear_deleted безопасен — для реального удаления нужно явно `dryRun=false`
4. **import_data: дубликаты**: без `updateExisting=true` создаются дубли, а не пропускаются
5. **Промпты**: содержат конкретные имена MCP-инструментов в плане действий — агент может следовать пошагово
6. **Ресурсы**: `ptm://registers` и `ptm://business-logic` дополняют `ptm://datamodel` — вместе дают полную картину конфигурации
