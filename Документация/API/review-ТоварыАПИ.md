# Review: HTTP-сервис `ТоварыАПИ` (legacy)

| Поле | Значение |
|------|----------|
| Объект | `Конфигурация/HTTPServices/ТоварыАПИ` |
| RootURL | `api` → `/hs/api/...` |
| Модуль | `ТоварыАПИ/Ext/Module.bsl` (~690 строк) |
| Дата review | 2026-08-12 |
| Вердикт | **Прототип / freeze.** Не развивать; мигрировать на `ptm/v1` (ADR-001) |

## Что делает сейчас

| Method | Template | Handler | Назначение |
|--------|----------|---------|------------|
| GET | `/search?code=` | `ПоискТовараGET` | Поиск номенклатуры |
| GET | `/goods/sync` | `СинхронизацияТоваровGET` | Выгрузка всех товаров |
| POST | `/check` | `ПриёмЧекаPOST` | Создание/проведение `ЧекККМ` |

## Паттерны (оставить / перенести)

| # | Что хорошо | Куда в v1 |
|---|------------|-----------|
| 1 | JSON + `Content-Type: application/json; charset=utf-8` | Адаптер `ПтмАпи` |
| 2 | HTTP-коды 400/404/500 на части сценариев | Единый `ErrorResponse` |
| 3 | Поиск: штрихкод → код → артикул | `ПтмАпиТовары` |
| 4 | Sync: штрихкоды **пакетом**, не query-in-loop на ШК | Application list |
| 5 | Чек: транзакция на `Записать(Проведение)` | Use-case create receipt |
| 6 | DTO-поля на EN (`code`, `name`, `price`) | Схемы OpenAPI `Product` |
| 7 | `ReuseSessions=DontUse` | Оставить для stateless API |

## Анти-паттерны (исправить в v1)

| # | Проблема | Риск | Целевое |
|---|----------|------|---------|
| 1 | **Вся логика в Module.bsl HTTP** (запросы, цены, проведение) | Нет переиспользования, тяжело тестировать | Тонкий HTTP + общие модули |
| 2 | **Глагольные URL** `/search`, `/goods/sync`, `/check` | Не REST, плохо масштабируется | `/products`, `POST /receipts` |
| 3 | **Нет версии** в path | Ломающие изменения бьют клиентов | `/v1/...` |
| 4 | **Нет auth на уровне API** (только auth публикации) | Любой с доступом к публикации = полный API | `X-Api-Key` + роль |
| 5 | **Envelope `success` + иногда 200 с ошибкой** (`РезультатОшибки` внутри 200) | Клиенты путают transport vs business | Status + `ErrorResponse` |
| 6 | **`ОписаниеОшибки()` в ответе** | Утечка внутренностей | `code` + safe `message` |
| 7 | **Full catalog sync без limit** + цена **в цикле** (`ПолучитьРозничнуюЦену` на каждый товар) | Timeout, нагрузка на ИБ | Пагинация / delta; пакет цен |
| 8 | **N+1 на поиск** (`ПолучитьДанныеТовара` + запрос + ШК на каждый hit) | Медленный multi-match | Пакетный fetch |
| 9 | **Склад/касса по наименованию** | Хрупко, дубли имён | Стабильный `code` / UUID |
| 10 | **Нет идемпотентности** на POST чека | Дубли чеков при retry | `Idempotency-Key` |
| 11 | **Нет `X-Request-Id` / аудита** | Невозможно связать логи клиента и 1С | Обязательный correlation |
| 12 | **Placeholder UUID в XML** (`a1b2c3d4-...`) | Риск коллизий/невалидности при загрузке | Реальные UUID платформы |
| 13 | **Дублирование** логики `ОбщегоНазначения.НайтиТовар` | Расхождение поведения UI vs API | Один application-метод |
| 14 | **Смешение ресурсов** (товары + чеки в одном «ТоварыАПИ») | Неверный bounded context | `products` + `receipts` |

## Карта миграции (legacy → v1)

| Legacy | v1 OpenAPI | Примечание |
|--------|------------|------------|
| `GET /hs/api/search?code=` | `GET /hs/ptm/v1/products?code=` | 404 если пусто и code задан; list если без code |
| `GET /hs/api/goods/sync` | `GET /hs/ptm/v1/products?limit=&offset=` | Обязательная пагинация; later: `updatedSince` |
| `POST /hs/api/check` | `POST /hs/ptm/v1/receipts` | 201 + `id`; `Idempotency-Key` |
| — | `GET /hs/ptm/v1/health` | Новый |
| — | `GET /hs/ptm/v1/products/{code}` | Удобный single-get |

Поля `Product` / `CreateReceipt*` уже отражают текущий JSON, с выравниванием enum оплат (`cash`/`card` + legacy labels).

## Приоритет рефакторинга (когда дойдём до кода)

1. Каркас модулей + auth + error + request-id (без смены URL клиентов).
2. `GET /products` + `GET /products/{code}` (замена search).
3. `POST /receipts` + idempotency (замена check).
4. Пагинированный list (замена goods/sync); оптимизация цен.
5. Deprecation legacy; dual-run; выключение `ТоварыАПИ`.

## Вывод

`ТоварыАПИ` — рабочий **вертикальный срез** (поиск / sync / чек), полезный как источник DTO и доменных шагов.  
Как **универсальный API** — не подходит: монолит модуля, RPC-URL, нет контракта/версии/ключа/пагинации/идемпотентности.

Дальше — реализация по ADR-001 и `openapi-v1.yaml`, не наращивание `ТоварыАПИ`.
