# ADR-002: Удалённый переучёт через кеш отчётов

| Поле | Значение |
|------|----------|
| Статус | Accepted |
| Дата | 2026-09-10 |
| Контекст | Public Trade Module (1С 8.3.27) |
| Спека | `Документация/Спецификации/2026-09-10-удаленный-переучет.md` |

## Решение

Мобильный переучёт **через интернет** идёт не в HTTP-сервис 1С и не в отдельный процесс, а в тот же сервис отчётов:

**https://reports.dojomyassiste.uno/inv**

- телефон читает/пишет SQLite-кеш **этого** процесса (штрихкоды, склады, факты) в таблицах `inv_*`, разрезанных по `user_id`;
- 1С доступна тем же туннелем, что уже задан в **Настройки** (`ib_location` + `X-Api-Key`);
- LAN-контур `/hs/mobile/inv/*` (если развёрнут) **не заменяется**.

Запись черновика в 1С — **write** к ресурсу `/inventories` (POST создать / PUT заменить ТЧ), не RPC `/sync`. Идемпотентность — `externalId` ↔ реквизит `ВнешнийИд`.

Отдельный сервис `remote_inventory/` (свой порт, свои учётки) **не используем**.

## Мотивация

1. Каждый скан в документ 1С по интернету медленный и ломается при недоступности ИБ.
2. Каталог ~3k штрихкодов помещается в SQLite целиком; полный pull по кнопке / раз в 15 минут достаточен.
3. Связь с ИБ **уже есть** на `reports.dojomyassiste.uno` (cookie `ptm_session`, туннель из Настроек). Второй процесс дублировал бы auth и URL ИБ.
4. Не публиковать файловую ИБ в интернет.

## Альтернативы (отклонены)

| Вариант | Почему нет |
|---------|------------|
| Кеш в регистрах 1С, телефон бьёт в 1С | ИБ всё ещё на критическом пути каждого скана |
| IndexedDB на телефоне | пользователь явно выбрал удалённый сервер, не локальный кеш устройства |
| Расширять LAN HTML `/hs/mobile` | LAN остаётся для кассы в магазине; другой auth и сеть |
| Отдельный Starlette на :8091 | уже есть живой сервис с теми же пользователями и тем же туннелем |

## Слои

```
Телефон (HTML + cookie ptm_session)
  → reports.dojomyassiste.uno/inv  (тот же uvicorn, SQLite inv_*)
     → PtmClient отчётов + ReportsPtmAdapter
        → [SSH-туннель из Настроек] PTM_API Апи_Внешний
           → Апи_Транспорт → Апи_Документы
              → Документ.ИнвентаризацияТоваров
```

HTTP-модуль 1С тонкий. Тело JSON и статус — в транспорте. Проведение документов с API запрещено.

## Последствия

- Нужен write в OpenAPI v1 (additive: POST/PUT `/inventories`). Read-журнал GET по-прежнему может быть 501.
- Реквизит `ВнешнийИд` в основной конфигурации.
- На VPS деплоится приложение `remote_reports/` (тот же origin `reports.dojomyassiste.uno`). Если старый процесс отчётов остаётся — модуль `app/inventory/` вставляется хуками из README.
- Учётки зала = учётки отчётов. Кеш каталога и черновики **на пользователя** (у каждого своя ИБ).
