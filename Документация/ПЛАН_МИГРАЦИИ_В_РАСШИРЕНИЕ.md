# План миграции объектов PTM в расширение PTM_Analytics.cfe

> Дата: 2026-03-17  
> Цель: ускорить цикл деплоя аналитических объектов с ~90 сек до ~15 сек  
> Статус: ЧЕРНОВИК — требует проверки перед реализацией

---

## Ключевой принцип

**НЕ мигрировать существующие объекты из основной конфигурации** — это опасно:
- UUID объекта при пересоздании в расширении изменится → сломаются ссылки
- Если объект используется в подписках / ОбщиеКоманды → потребуется ручная правка
- Требует UpdateDBCfg в основной конфигурации при удалении старого объекта

**Правильная стратегия: зелёный путь (greenfield)**  
→ Все НОВЫЕ отчёты, обработки, утилиты — сразу в расширение  
→ Существующие объекты остаются в основной конфигурации до естественного рефактора

## Что идёт в расширение PTM_Analytics.cfe

### ✅ Полностью безопасно (новые объекты)

| Тип | Что переносить | Ограничения |
|-----|----------------|-------------|
| **Отчёты (Reports)** | Все новые аналитические отчёты | Не могут напрямую переопределять регистры — только читать |
| **Обработки (DataProcessors)** | Утилиты: импорт/экспорт, загрузка цен, тест-данные | Не могут создавать новые типы регистраторов |
| **Общие модули** | Утилитные модули без &НаСервере без ПовторногоИспользования | Нельзя переопределять функции основной конфигурации |
| **Регламентные задания** | Новые фоновые задачи | Если нет зависимости от констант основной конфигурации |

### ❌ Остаётся в основной конфигурации ВСЕГДА

| Тип | Причина |
|-----|---------|
| Документы (все 11) | Определяют структуру таблиц, регистраторы |
| Справочники (все) | Первичные данные, UUID используются повсюду |
| Регистры накопления | Структура БД |
| Регистры сведений | Структура БД |
| Перечисления | Ссылки на них жёстко зашиты в коде |
| Планы видов характеристик | Структура БД |
| Константы | Глобальные настройки |
| SessionParameters | Инициализируются при старте |
| DefinedTypes | Типизация |
| Подсистемы | Навигация |
| Роли | Права доступа |
| Языки | Локализация |

### ⚠️ Существующие объекты — оставить, не трогать

Эти объекты уже в основной конфигурации. Миграция создаст риски:

```
Reports/             ← ВаловаяПрибыль, Взаиморасчеты, Возвраты, ДвижениеДенег, 
                        ДвижениеТоваров, ОстаткиТоваров, Продажи, ПродажиЗаСмену,
                        ПродажиПоСчетам
DataProcessors/      ← РабочееМестоКассира, ОткрытьКассу, ЗагрузкаЗакупочныхЦен, etc.
```

```

    ├── DataProcessors/    ← новые утилиты и обработки
    └── CommonModules/     ← вспомогательные модули
```

## Пошаговый план реализации

### Фаза 1 (немедленно): Создать PTM_Analytics и инструменты

#### 1.1 Инструменты готовы ✅

```bash
# scripts/deploy_ext.py — уже создан
python scripts/deploy_ext.py --ext PTM_Analytics --action Full    # ~15 сек
python scripts/deploy_ext.py --ext PTM_Analytics --action Dump    # выгрузить из ИБ
python scripts/deploy_ext.py --ext PTM_Analytics --action Load    # загрузить в ИБ
python scripts/deploy_ext.py --ext PTM_Analytics --action Update  # только UpdateDBCfg
python scripts/deploy_ext.py --ext PTM_Analytics --action Check   # Dump + список файлов
```

#### 1.2 Создать расширение в ИБ (одноразово, вручную)

1. Конфигуратор → `Конфигурация → Расширения конфигурации → Создать`
   - Имя: `PTM_Analytics`
   - Синоним: `PTM Аналитика`
   - Режим безопасности: выключить
2. Сохранить → закрыть Конфигуратор
3. Выгрузить в файлы:
   ```bash
   python scripts/deploy_ext.py --ext PTM_Analytics --action Dump
   ```
   Файлы появятся в `Конфигурация_PTM_Analytics/`
4. Добавить в git: `git add Конфигурация_PTM_Analytics/`

#### 1.3 Команды расширения Designer (справка)

```
# Загрузить из файлов в ИБ:
Designer /F <ИБ> /LoadConfigFromFiles <папка> -Extension PTM_Analytics

# Выгрузить из ИБ в файлы:
Designer /F <ИБ> /DumpConfigToFiles <папка> -Extension PTM_Analytics

# Обновить БД расширения:
Designer /F <ИБ> /UpdateDBCfg -Extension PTM_Analytics
```

### Фаза 2 (следующий новый отчёт): Первый объект в расширении

При создании следующего аналитического отчёта:
1. Открыть Конфигуратор → Расширения → PTM_Analytics → добавить отчёт
2. Разработать отчёт → сохранить
3. Выгрузить + задеплоить:
   ```bash
   python scripts/deploy_ext.py --ext PTM_Analytics --action Dump   # фиксируем в файлы
   python scripts/deploy_ext.py --ext PTM_Analytics --action Full   # деплой ~15 сек
   ```
4. Замерить время → записать в ЖУРНАЛ_ПРОИЗВОДИТЕЛЬНОСТИ.md

## Ограничения расширений (знать заранее)

### Что расширение НЕ может делать

1. **Не может создавать новые регистры** — только читать существующие
2. **Не может добавлять реквизиты к справочникам/документам** — только общие реквизиты через ОпределяемыеТипы
3. **Не может изменять модуль проведения документа** — только подписки на события
4. **Не может переопределять функции общих модулов** — только добавлять новые
5. **Не может менять права доступа** — только новые роли для новых объектов расширения

### Что расширение МОЖЕТ делать

1. ✅ Новые отчёты с запросами к любым регистрам основной конфигурации
2. ✅ Новые обработки для работы с любыми объектами
3. ✅ Новые общие формы
4. ✅ Новые общие команды (для добавления в подсистемы)
5. ✅ Новые роли (только для объектов расширения)
6. ✅ Аннотировать (подписки) формы документов из основной конфигурации

## Изменения в CI/deploy-скриптах

### Новая команда Designer для расширений

```powershell
# Загрузка расширения из файлов в ИБ:
& $designer /F $ibPath /LoadExt /ExtensionName "PTM_Analytics" ^
    /ExtensionDir "$configExtDir" /Out $logFile

# Проверка расширения:
& $designer /F $ibPath /CheckExtension "PTM_Analytics" /Out $logFile

# Обновление ИБ с расширением:
& $designer /F $ibPath /UpdateIBExt "PTM_Analytics" /Out $logFile
```

## Риски и митигация

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Расширение несовместимо с обновлением платформы | Низкая (8.3.27 стабильная) | Тест перед деплоем |
| Конфликт имён объектов с основной конф. | Средняя | Префикс `аПТМ_` для всех объектов расширения |
| Производительность: расширение добавляет overhead | Низкая для отчётов | Только аналитические объекты, не горячий путь |
| MCP не видит объекты расширения | Возможна | MCP уже работает с расширением, проверить отдельно |

## Вывод: нужно ли это делать сейчас?

**Да, если:**
- В ближайший месяц планируются 3+ новых отчёта/обработки
- Часто меняется логика существующих отчётов (BSL без добавления реквизитов)

**Нет, если:**
- Основная работа — изменение структуры документов/регистров (всё равно нужен полный деплой)
- Команда одна и деплой не параллелится

**Рекомендация:** Начать с Фазы 1 (создать расширение) и Фазы 2 (первый новый объект в расширении). Это даст реальные данные о выигрыше без риска для существующей конфигурации.
