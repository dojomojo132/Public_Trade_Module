# Workflow: Конфигуратор + Агент

> **Дата:** 2026-03-30  
> **Версия:** 1.0  
> **Проблема:** Агент отлично пишет BSL-код, но при создании XML-объектов/форм/реквизитов допускает ошибки, которые крашат ИБ или блокируют деплой  
> **Решение:** Разделить ответственность — структура создаётся пользователем в Конфигураторе, код пишет агент

---

## Принцип разделения

```
┌─────────────────────────────────┐    ┌─────────────────────────────────┐
│     КОНФИГУРАТОР (пользователь) │    │        АГЕНТ (Copilot)          │
│                                 │    │                                 │
│  ✅ Новые объекты метаданных    │    │  ✅ BSL-код модулей объектов     │
│  ✅ Реквизиты и табличные части │    │  ✅ BSL-код модулей форм         │
│  ✅ Формы (визуальный дизайн)   │    │  ✅ СКД-шаблоны (Template.xml)   │
│  ✅ Подсистемы и роли           │    │  ✅ Ревью и рефакторинг кода     │
│  ✅ Перечисления                │    │  ✅ Запросы 1С                   │
│  ✅ Регистры (структура)        │    │  ✅ Диагностика и дебаг          │
│  ✅ HTTP-сервисы (структура)    │    │  ✅ Деплой и мониторинг          │
│  ✅ Расширения (создание)       │    │  ✅ Тесты                        │
│                                 │    │  ✅ Документация и Obsidian       │
└─────────────┬───────────────────┘    └──────────────┬──────────────────┘
              │                                       │
              │         ┌──────────────┐              │
              └────────►│  Dump / Deploy│◄─────────────┘
                        │  (синхрон.)  │
                        └──────────────┘
```

## Полный цикл задачи

### Сценарий A: Новая функциональность (новый объект)

```
ФАЗА 0: ПОДГОТОВКА
  Пользователь формулирует задачу агенту
  Агент анализирует (MCP + файлы) и выдаёт ТЗ:
    — какие объекты нужно создать (с типами, реквизитами, ТЧ)
    — какие формы нужны
    — в какие подсистемы добавить
    — какой BSL-код потребуется

ФАЗА 1: КОНФИГУРАТОР (пользователь)
  1. Открыть Конфигуратор
  2. Создать объект(ы) по ТЗ агента:
     — Добавить реквизиты, табличные части, типы
     — Создать формы (пустые или с базовой разметкой)
     — Добавить в подсистему
  3. Обновить конфигурацию БД (F7)
  4. ЗАКРЫТЬ Конфигуратор (обязательно!)

ФАЗА 2: СИНХРОНИЗАЦИЯ (Dump)
  Агент выполняет:
    python scripts/_ps_wrapper.py deploy -Action Dump
  Результат: актуальные XML-файлы появляются в Конфигурация/

ФАЗА 3: КОДИРОВАНИЕ (агент)
  Агент пишет BSL-код:
    — Модули объектов (проведение, подписки, обработчики)
    — Модули форм (клиентские обработчики, серверные функции)
    — СКД-шаблоны (если отчёт)
  Агент проверяет:
    — get_errors на все .bsl файлы → 0 ошибок
    — validate-config.ps1 → 0 новых ошибок

ФАЗА 4: ДЕПЛОЙ (агент)
  python scripts/_ps_wrapper.py deploy -Action Full
  или (для расширения):
  python scripts/deploy_ext.py --ext <Имя> --action Full

ФАЗА 5: МОНИТОРИНГ (агент)
  python scripts/_ps_wrapper.py monitor -Action Check -LastMinutes 5
  — 0 ошибок → успех
  — Есть ошибки → агент исправляет BSL → повторный деплой

ФАЗА 6: ЗАВЕРШЕНИЕ
  — Обновить спецификацию
  — Обновить Obsidian Knowledge Graph
  — Git commit (после подтверждения пользователя)
```

### Сценарий B: Изменение существующего объекта (только код)

```
ФАЗА 0: Dump → Агент пишет код → Deploy → Monitor
(стандартный текущий workflow, без Конфигуратора)
```

### Сценарий C: Добавить реквизит к существующему объекту + логику

```
ФАЗА 0: ПОДГОТОВКА
  Агент формулирует: "Добавьте реквизит Х типа Y в объект Z"

ФАЗА 1: КОНФИГУРАТОР (пользователь)
  1. Добавить реквизит
  2. При необходимости — обновить форму (перетащить реквизит)
  3. F7 → ЗАКРЫТЬ Конфигуратор

ФАЗА 2: Dump → Агент пишет код → Deploy → Monitor
```

## Что агент выдаёт в качестве ТЗ для Конфигуратора

Формат ТЗ, которое агент готовит перед Фазой 1:

```markdown
## ТЗ для Конфигуратора

### Создать документ: ПеремещениеТоваров
- Числовая длина: 11
- Реквизиты шапки:
  | Имя | Тип | Обязательный |
  |-----|-----|-------------|
  | Склад | СправочникСсылка.Склады | Да |
  | СкладПолучатель | СправочникСсылка.Склады | Да |
  | Комментарий | Строка(200) | Нет |

- Табличная часть: Товары
  | Имя | Тип |
  |-----|-----|
  | Номенклатура | СправочникСсылка.Номенклатура |
  | Количество | Число(15,3) |
  | Цена | Число(15,2) |
  | Сумма | Число(15,2) |

- Формы:
  | Имя | Тип | Основная |
  |-----|-----|----------|
  | ФормаДокумента | Форма документа | Да |
  | ФормаСписка | Форма списка | Да |

- Подсистема: Склад
- Движения: РегистрНакопления.ОстаткиТоваров (расход + приход)

### После создания:
1. Обновить БД (F7)
2. Закрыть Конфигуратор
3. Написать "готово" в чат
```

## Команды синхронизации

### После работы в Конфигураторе → файлы для агента:

```bash
# Dump основной конфигурации (~5 сек)
python scripts/_ps_wrapper.py deploy -Action Dump

# Dump расширения (~5 сек)
python scripts/deploy_ext.py --ext PTM_Analytics --action Dump
```

### После работы агента → в Конфигуратор:

```bash
# Деплой основной конфигурации (~100 сек)
python scripts/_ps_wrapper.py deploy -Action Full

# Деплой расширения (~15 сек)
python scripts/deploy_ext.py --ext PTM_Analytics --action Full
```

## Что это устраняет

### Проблемы, которые ПОЛНОСТЬЮ уходят (90% потерянного времени):

| # | Проблема | Почему уходит |
|---|----------|---------------|
| 1 | Нет записи в ConfigDumpInfo.xml | CDI генерируется Конфигуратором автоматически |
| 2 | Нет записи в Configuration.xml | Configuration.xml обновляется автоматически |
| 3 | Double BOM в XML | Конфигуратор управляет кодировкой |
| 4 | Ошибка формата потока (крэш ИБ) | Несовместимые XML не сохранятся |
| 5 | URLTemplate=/ (C++ crash) | Конфигуратор валидирует при сохранении |
| 6 | Command без Action | Action создаётся при привязке в UI |
| 7 | Form.xml owner vs Properties | Корректный XML генерируется автоматически |
| 8 | FillFromFillingValue у обработки | Свойство не появится в UI |
| 9 | Незарегистрированные DataProcessors | Создание через дерево = авторегистрация |

### Проблемы, которые ОСТАЮТСЯ:

| # | Проблема | Решение |
|---|----------|---------|
| 1 | Сеансы блокируют деплой | Закрывать Конфигуратор перед деплоем |
| 2 | Таймаут LoadConfig | Адекватные таймауты в скриптах |
| 3 | Exit code 1 = false negative | Улучшить парсинг exit code в скриптах |

## Изменения в поведении агента

### Что меняется в orchestrator:

```diff
ФАЗА 1: РЕАЛИЗАЦИЯ (было)
- Агент создаёт XML объекта из шаблона
- Агент генерирует UUID
- Агент обновляет Configuration.xml
- Агент обновляет ConfigDumpInfo.xml
- Агент создаёт форму через _generate_form.py

ФАЗА 1: РЕАЛИЗАЦИЯ (стало)
+ Агент готовит ТЗ для Конфигуратора
+ Пользователь создаёт объект в Конфигураторе
+ Пользователь создаёт формы в Конфигураторе
+ Dump → файлы синхронизированы
+ Агент ТОЛЬКО пишет BSL-код в уже готовую структуру
```

### Что агент ПЕРЕСТАЁТ делать:

```
❌ Генерировать UUID для объектов метаданных
❌ Создавать XML объектов с нуля из шаблонов
❌ Обновлять Configuration.xml (ChildObjects)
❌ Обновлять ConfigDumpInfo.xml
❌ Создавать Form.xml (структура формы)
❌ Добавлять реквизиты/ТЧ в XML объектов
❌ Менять структуру подсистем
```

### Что агент ПРОДОЛЖАЕТ делать:

```
✅ Писать BSL-код (ObjectModule, ManagerModule, FormModule)
✅ Редактировать существующий BSL
✅ Создавать/редактировать СКД-шаблоны (Template.xml для отчётов)
✅ Диагностировать ошибки
✅ Деплоить (deploy/dump)
✅ Мониторить (журналы, ТЖ)
✅ Обновлять спецификацию и Obsidian
✅ Git commit
✅ Проводить ревью кода
```

## Когда НЕ нужен Конфигуратор

Агент продолжает работать самостоятельно (без Конфигуратора) для:

1. **Чисто кодовые задачи** — изменение логики модулей, исправление багов в BSL
2. **СКД-отчёты** — Template.xml для отчётов (это данные, не метаданные)
3. **Расширения (существующие)** — если расширение уже создано, агент может добавлять код
4. **Мониторинг и диагностика** — проверка логов, анализ ошибок
5. **Документация** — спецификации, Obsidian
6. **Тесты** — YAxUnit, smoke-тесты

## Интеграция в интерактивный диалог

### Новый диалог: `configurator_task`

Когда агент определяет, что задача требует создания нового объекта/формы/реквизита:

```json
{
  "header": "configurator_task",
  "question": "Для этой задачи нужно создать объект(ы) в Конфигураторе.\nТЗ подготовлено выше.\n\nСоздайте объекты и напишите 'готово'.",
  "options": [
    { "label": "✅ Готово — объекты созданы, Конфигуратор закрыт" },
    { "label": "❓ Вопрос по ТЗ — нужно уточнить" },
    { "label": "🔄 Пусть агент сам создаст через XML (старый способ)" },
    { "label": "🔴 Отмена — задача неактуальна" }
  ],
  "allowFreeformInput": true
}
```

### Обработка ответов:

- **"Готово"** → агент запускает Dump → проверяет что объект появился → пишет код
- **"Вопрос"** → агент уточняет ТЗ
- **"Агент сам"** → fallback на старый XML-workflow (с рисками)
- **"Отмена"** → завершение задачи
