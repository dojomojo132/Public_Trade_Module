### 1.3 Почему именно YAxUnit + Vanessa Automation

**YAxUnit** (рекомендация № 1 для unit/интеграционных тестов):
- Современный инструмент (2022-2026), активно развивается компанией BIA-Technologies
- Работает как **расширение конфигурации** (не внешняя обработка) — проще интегрировать
- Поддерживает **Мокито** (подмена поведения методов) — критично для PTM с БПО-зависимостями
- Текучий API: `ЮТест.ОжидаетЧто(Результат).Равно(4)` — читаемый код
- Конструктор тестовых данных: `ЮТест.Данные().КонструкторОбъекта("Документ.ЧекККМ")`
- Утверждения для проверки данных ИБ: `ЮТест.ОжидаетЧтоТаблицаБазы(...)` — проверка движений
- Отчёты в формате **JUnit XML** и **Allure** — интегрируется с CI
- Дымовые тесты из коробки (открытие всех форм)
- Плагин для EDT

**Vanessa Automation** (рекомендация для UI/сценарного тестирования):
- Самый зрелый BDD-инструмент для 1С (611 stars, 99 контрибьюторов)
- Gherkin-сценарии на русском (TurboGherkin)
- Запись действий пользователя в сценарий (Record & Play)
- Встроенный редактор сценариев (VAEditor на базе VS Code)
- Генерация автодокументации и видеоинструкций
- Консольный запуск для CI/CD
- Allure-отчёты

## 2. Что тестирование даст проекту PTM

### 2.1 Конкретная польза

| Проблема (сейчас) | Решение через тестирование | Выгода |
|---|---|---|
| Ошибки при изменении XML/BSL ломают конфигурацию → откаты, потеря данных | **Дымовые тесты** — автопроверка открытия всех форм после деплоя | Больше не нужно вручную проверять каждую форму |
| Устаревший код (`ТекущаяДата()`, `ПоказатьВопрос()` — 7+18 мест) | **BSL LS диагностики** в CI — блокируют merge при нарушениях | Устаревший код не попадёт в конфигурацию |
| Проведение документов — сложная логика с движениями по 5 регистрам | **Unit-тесты движений** — проверка что ЧекККМ/ПриходТовара создают правильные записи | Рефакторинг модулей проведения без страха |
| РабочееМестоКассира — критичная обработка (~700 строк BSL) | **Сценарные тесты**: пробитие чека, возврат, оплата картой, скидка | Регрессия ловится до попадания в продакшен |
| Расчёт скидок по дисконтным картам | **Unit-тесты расчётов** с различными параметрами | Гарантия правильности скидок |
| Переоценка товаров — автосоздание документов | **Интеграционные тесты**: переоценка → проверка движений по регистрам | Контроль корректности переоценки |
| ИмпортНоменклатуры из Excel — хрупкий парсинг | **Unit-тесты импорта** с тестовыми данными | Изменение формата Excel не сломает импорт |
| Ненадёжный `ИмяПользователя()` для определения сотрудника (кат. 5) | **Тест на определение сотрудника** покажет проблему | Быстрое обнаружение ненадёжного кода |
| КассоваяСмена с пустым RegisterRecords (кат. 6) | **Тест проведения** покажет что движений нет | Формальная фиксация бага |

### 2.2 ROI (окупаемость)

```
ИНВЕСТИЦИЯ:                          ЭКОНОМИЯ:
─────────────                        ──────────
~3-5 дней на базовую настройку       Каждый деплой: -30 мин ручной проверки
```

## 3. План внедрения (поэтапный)

### Этап 0: Статический анализ (уже частично есть)
**Срок:** 0.5-1 день  
**Статус:** BSL Language Server уже работает в VS Code

| Задача | Инструмент | Описание |
|--------|-----------|----------|
| Настроить `.bsl-language-server.json` | BSL LS | Включить все рекомендованные диагностики для PTM-модулей |
| Добавить проверку в `deploy-config.ps1` | BSL LS CLI | `bsl-language-server -a -s Конфигурация/Проверка/ -r genericIssue` |
| Блокировать деплой при ошибках | PowerShell | Проверка `exit code` BSL LS перед загрузкой в ИБ |

**Конфигурация `.bsl-language-server.json`:**
```json
{
  "diagnostics": {
    "computeTrigger": "onSave",
    "parameters": {
      "UsingModalWindows": true,
      "DeprecatedCurrentDate": true,
      "UsingFindElementByString": true,
      "EmptyCodeBlock": true,
      "MissingCodeTryCatchEx": true,
      "BeginTransactionBeforeTryCatch": true,
      "CommitTransactionOutsideTryCatch": true,
      "RollbackTransactionOutsideTryCatch": true
    }
  }
}
```

### Этап 1: Дымовые тесты (YAxUnit)
**Срок:** 1-2 дня  
**Цель:** автоматическое открытие всех форм конфигурации

| Задача | Описание |
|--------|----------|
| Установить YAxUnit | Скачать cfe с GitHub, загрузить как расширение в тестовую ИБ |
| Настроить тестовую ИБ | Копия рабочей базы (или создать из .dt) для прогона тестов |
| Включить дымовые тесты | YAxUnit имеет встроенный генератор дымовых тестов |
| Проверить открытие форм | Автоматически открывает все формы всех объектов метаданных |

**Что проверяется дымовыми тестами:**
```
✓ Открытие форм документов: ЧекККМ, ПриходТовара, Переоценка...
✓ Открытие форм справочников: Номенклатура, Контрагенты, Кассы...
✓ Открытие форм отчётов: ОстаткиТоваров, Продажи, ВаловаяПрибыль...
✓ Открытие формы РабочееМестоКассира
✓ Форма списка всех объектов
✓ Новые элементы/документы (без записи)
```

### Этап 2: Unit-тесты бизнес-логики (YAxUnit)
**Срок:** 3-5 дней  
**Цель:** покрытие критичной серверной логики

#### 2.1 Тесты проведения документов

**Приоритет 1 — ЧекККМ (центральный документ)**
```bsl
// Пример структуры теста проведения ЧекККМ
Процедура ИсполняемыеСценарии() Экспорт
    ЮТТесты
        .ДобавитьТест("ПроведениеЧекаССоздаётДвиженияОстатковТоваров")
        .ДобавитьТест("ПроведениеЧекаСоздаётДвиженияПродаж")
        .ДобавитьТест("ПроведениеЧекаСоздаётДвиженияДенежныхСредств")
        .ДобавитьТест("ПроведениеВозвратаСоздаётОбратныеДвижения")
        .ДобавитьТест("АннулированныйЧекНеСоздаётДвижения")
    ;
КонецПроцедуры

Процедура ПроведениеЧекаССоздаётДвиженияОстатковТоваров() Экспорт
    // GIVEN: Номенклатура с остатком 10 шт
    Номенклатура = ЮТест.Данные().СоздатьЭлемент("Справочники.Номенклатура");
    Склад = ЮТест.Данные().СоздатьЭлемент("Справочники.Склады");
    
    // WHEN: Проводим чек на 3 шт
    Чек = ЮТест.Данные().КонструкторОбъекта("Документы.ЧекККМ")
        .Установить("Дата", ТекущаяДатаСеанса())
        .Установить("Склад", Склад)
        .ТабличнаяЧасть("Товары")
            .ДобавитьСтроку()
            .Установить("Номенклатура", Номенклатура)
            .Установить("Количество", 3)
            .Установить("Цена", 100)
            .Установить("Сумма", 300)
        .Записать();
    
    // THEN: Движение по РН ОстаткиТоваров = -3
    ЮТест.ОжидаетЧтоТаблицаБазы("РегистрНакопления.ОстаткиТоваров")
        .Содержит()
        .Поле("Номенклатура").Равно(Номенклатура)
        .Поле("Количество").Равно(3);
КонецПроцедуры
```

**Приоритет 2 — ПриходТовара**
```
Тесты:
- Проведение прихода → +остатки на складе
- Проведение с ценами → обновление РС ЦеныНоменклатуры
- Проведение с контрагентом → движения по Взаиморасчёты
```

**Приоритет 3 — Переоценка**
```
Тесты:
- Переоценка номенклатуры → обновление РС ЦеныНоменклатуры
- Массовая переоценка → корректные движения для каждой позиции
- Переоценка с автосозданием док-та → проверка даты = ТекущаяДатаСеанса()
```

### Этап 4: Интеграция в CI/CD
**Срок:** 1-2 дня  
**Цель:** автоматический запуск тестов при каждом деплое

#### 4.1 Расширение deploy-config.ps1

```
ТЕКУЩИЙ PIPELINE:
  git backup → validate XML → Load Config → Syntax check → Update DB → OK

ОБНОВЛЁННЫЙ PIPELINE:
  git backup 
    → validate XML 
    → BSL LS diagnostics (статический анализ) ← НОВОЕ
    → Load Config 
    → Syntax check 
    → Update DB 
    → YAxUnit smoke tests ← НОВОЕ
    → YAxUnit unit tests  ← НОВОЕ
    → OK / FAIL с отчётом
```

#### 4.2 Скрипт запуска тестов

```powershell
# run-tests.ps1 — добавить в pipeline после деплоя

# Запуск YAxUnit из командной строки
$V83 = "C:\Program Files\1cv8\8.3.27.xxxx\bin\1cv8.exe"
$IB = "/F D:\1C_Bases\PTM_Test"

# Параметры запуска YAxUnit
$YAXParams = @{
    "reportPath" = "D:\Git\Public_Trade_Module\test-reports\"
    "reportFormat" = "junitxml"
    "closeAfter" = $true
}

# Сериализовать в JSON
$ParamsJson = $YAXParams | ConvertTo-Json
$ParamsFile = "D:\Git\Public_Trade_Module\yaxunit-params.json"
$ParamsJson | Out-File -FilePath $ParamsFile -Encoding UTF8

# Запустить тесты
& $V83 ENTERPRISE $IB /C"RunUnitTests=$ParamsFile" /DisableStartupDialogs
```

| **Проверка деплоя** | Ручная: открыть формы, посмотреть | Автоматическая: дымовые тесты за 2 мин |
| **Рефакторинг** | Страшно менять — сломается | Безопасно: тесты покажут что сломалось |
| **Код-ревью** | Визуальный просмотр BSL | BSL LS + unit-тесты блокируют плохой код |
| **Регрессия** | Обнаруживается пользователями | Обнаруживается до деплоя |
| **Документация РМК** | Нет | Vanessa автогенерирует видео/скриншоты |
| **Устаревший код** | Копится (7 мест `ТекущаяДата()`) | BSL LS не даёт коммитить новый |
| **Время деплоя** | ~15 мин (+ 30 мин ручная проверка) | ~20 мин (всё автоматически) |
| **Уверенность в релизе** | Низкая | Высокая (зелёные тесты = OK) |

## 6. Технические детали интеграции

### 6.1 Установка YAxUnit

```
1. Скачать последний релиз: https://github.com/bia-technologies/yaxunit/releases
2. Файл: yaxunit-XX.XX.cfe
3. Загрузить в тестовую ИБ как расширение конфигурации:
   Конфигуратор → Конфигурация → Расширения конфигурации → Добавить из файла
4. Снять галочки "Безопасный режим" и "Защита от опасных действий"
5. Обновить БД
```

### 6.2 Создание расширения с тестами PTM

```
1. Создать новое расширение: "ТестыPTM" 
2. Назначение: Дополнение (не Адаптация/Исправление)
3. Добавить общие модули:
   - ОМ_ТестыЧекККМ         (Сервер, ВызовСервера)
   - ОМ_ТестыПриходТовара    (Сервер, ВызовСервера)
   - ОМ_ТестыПереоценка      (Сервер, ВызовСервера)
   - ОМ_ТестыОбщегоНазначения (Сервер)
   - ОМ_ТестыРасчётов        (Сервер)
   - ОМ_ДымовыеТесты         (Сервер) — если не используется встроенный генератор
```

### 6.3 Пример модуля тестов для ЧекККМ

```bsl
// Общий модуль: ОМ_ТестыЧекККМ
// Сервер, ВызовСервера

#Область ПрограммныйИнтерфейс

Процедура ИсполняемыеСценарии() Экспорт
    
    ЮТТесты
        .ДобавитьТестовыйНабор("Проведение чека ККМ")
            .ДобавитьТест("ПроведениеЧекаСоздаётДвиженияОстатков")
            .ДобавитьТест("ПроведениеЧекаСоздаётДвиженияПродаж")
            .ДобавитьТест("ПроведениеЧекаСоздаётДвиженияДенежныхСредств")
            .ДобавитьТест("ПроведениеЧекаСДисконтнойКартой")
            .ДобавитьТест("АннулированныйЧекНеСоздаётДвижения")
        .ДобавитьТестовыйНабор("Валидация чека")
            .ДобавитьТест("ЧекБезТоваровНеПроводится")
            .ДобавитьТест("ЧекБезСкладаНеПроводится")
            .ДобавитьТест("ЧекСНулевойСуммойНеПроводится")
    ;
    
КонецПроцедуры

Процедура ПроведениеЧекаСоздаётДвиженияОстатков() Экспорт
    
    // Подготовка данных
    Склад = ЮТест.Данные().СоздатьЭлемент("Справочники.Склады",
        Новый Структура("Наименование", "Тестовый склад"));
    
    Товар = ЮТест.Данные().СоздатьЭлемент("Справочники.Номенклатура",
        Новый Структура("Наименование", "Тестовый товар"));
    
    // Создание и проведение чека
    Чек = ЮТест.Данные().КонструкторОбъекта("Документы.ЧекККМ")
        .Установить("Дата", ТекущаяДатаСеанса())
        .Установить("Склад", Склад)
        .ТабличнаяЧасть("Товары")
            .ДобавитьСтроку()
            .Установить("Номенклатура", Товар)
            .Установить("Количество", 5)
            .Установить("Цена", 100)
            .Установить("Сумма", 500)
        .Записать();
    
    // Проверка: движения по регистру ОстаткиТоваров
    ЮТест.ОжидаетЧтоТаблицаБазы("РегистрНакопления.ОстаткиТоваров")
        .СодержитЗаписи()
        .Поле("Регистратор").Равно(Чек)
        .Поле("Номенклатура").Равно(Товар)
        .Поле("Склад").Равно(Склад)
        .Поле("Количество").Равно(5);
    
КонецПроцедуры

Процедура АннулированныйЧекНеСоздаётДвижения() Экспорт
    
    // У аннулированного чека не должно быть движений
    // Статус = Перечисления.СтатусыЧекаККМ.Аннулирован
    
    Склад = ЮТест.Данные().СоздатьЭлемент("Справочники.Склады");
    Товар = ЮТест.Данные().СоздатьЭлемент("Справочники.Номенклатура");
    
    Чек = ЮТест.Данные().КонструкторОбъекта("Документы.ЧекККМ")
        .Установить("Дата", ТекущаяДатаСеанса())
        .Установить("Склад", Склад)
        .Установить("Статус", Перечисления.СтатусыЧекаККМ.Аннулирован)
        .ТабличнаяЧасть("Товары")
            .ДобавитьСтроку()
            .Установить("Номенклатура", Товар)
            .Установить("Количество", 1)
            .Установить("Цена", 100)
            .Установить("Сумма", 100)
        .Записать();
    
    // Проверка: движений нет
    ЮТест.ОжидаетЧтоТаблицаБазы("РегистрНакопления.ОстаткиТоваров")
        .НеСодержитЗаписей()
        .Поле("Регистратор").Равно(Чек);
    
КонецПроцедуры

#КонецОбласти
```

### 6.4 Запуск тестов

## 8. Метрики успеха

| Метрика | Целевое значение | Как измерять |
|---------|-----------------|-------------|
| Покрытие дымовыми тестами | 100% форм PTM | Отчёт YAxUnit |
| Покрытие unit-тестами | >80% модулей проведения | Отчёт YAxUnit |
| Время прогона всех тестов | < 5 минут | CI-лог |
| Ошибки BSL LS при деплое | 0 | Выход BSL LS |
| Регрессий в продакшене | -50% за квартал | Лог инцидентов |
| Новый код без тестов | 0% (правило) | Код-ревью |

## 9. Риски и митигация

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Тесты будут падать из-за БПО-зависимостей | Высокая | Мокито (мок БПО-модулей) в YAxUnit |
| Тестовая ИБ рассинхронизируется с рабочей | Средняя | Автокопирование .dt перед тестами |
| Сценарные тесты хрупкие (привязка к UI) | Средняя | Использовать подсценарии, DataPath вместо заголовков |
| Замедление деплоя | Низкая | Параллельный запуск, быстрые тесты (<5 мин) |
| Сопротивление команды | Средняя | Начать с дымовых (минимум усилий, максимум пользы) |
