### Ключевая особенность
Конфигурация плотно завязана на **Библиотеку Подключаемого Оборудования (БПО)** — это ~70% общих модулей. БПО обеспечивает работу с ККТ (54-ФЗ, ФФД 1.2), эквайринговыми терминалами, весами, сканерами, принтерами этикеток, RFID и т.д.

### Существующие точки интеграции

| Слой | Описание | Протокол | Эндпоинты |
|------|---------|----------|-----------|
| **REST API** (`/api/`) | Поиск товаров, синхронизация каталога, приём чеков | JSON/HTTP | 3 эндпоинта |
| **Mobile API** (`/ptm/hs/mobile/`) | Логин, кассовые смены, корзина, сканирование | JSON/HTTP | 6 эндпоинтов |
| **SOAP** (`EquipmentService`) | Управление устройствами, прайс-листы, документы | SOAP/XML | 11 операций |
| **Web App** | Мобильная касса (vanilla JS + камера + barcode) | HTML5/SPA | 1 SPA |

## 3. Главные трудности при миграции

### 3.1 Фискальное оборудование (БЛОКИРУЮЩАЯ ПРОБЛЕМА)

~100 общих модулей БПО покрывают: ККТ (АТОЛ, Штрих-М, Дримкас, Эвотор и др.), ФФД 1.2, маркировку, облачные кассы, платёжные терминалы. В 1С это **встроено в платформу**. В альтернативе — с нуля.

- **Трудозатраты:** 6–12 месяцев только на фискализацию
- **Стоимость:** +$10-50K (Odoo), +$50-200K (кастом)
- **Риск:** ФФД 1.3 на подходе

### 3.2 Модель «Документ → Проведение → Регистры»

1С автоматически поддерживает целостность: документ при проведении формирует движения по 5 регистрам. В веб-фреймворках — реализация вручную (транзакции, контроль, откат).

- **Трудозатраты:** 6-12 месяцев
- **Риск:** Нарушение целостности данных при ошибках

### 3.3 Управляемые формы UI

POS-интерфейс для кассиров. В 1С — декларативно (XML + BSL). В вебе — React/Vue + REST API = кратно больше кода.

- **Трудозатраты:** 3-6 месяцев

### 3.4 Оффлайн-работа и синхронизация

Offline-оборудование (Эвотор, 1С:ККМ) имеет встроенные механизмы обмена. При миграции — своя система синхронизации.

### 3.5 Переобучение команды

BSL → Python/Java/C# — смена парадигмы (предметно-ориентированный → универсальное программирование).

- **Трудозатраты:** 2-4 месяца обучения

### 3.6 «Тихие блокеры» (почему миграция часто проваливается)

1. Фискальная интеграция недооценена
2. Миграция данных: Document→Register не маппится на GL
3. Переобучение кассиров: веб-UI медленнее
4. Экосистема 1С: банки, ОФД, логистика — всё интегрировано
5. Vendor lock-in: выход из 1С стоит столько же, сколько вход в альтернативу

## 4. Рекомендации по сценариям

| Сценарий | Рекомендация | Сроки | Стоимость |
|----------|-------------|-------|-----------|
| **Снизить издержки на 1С** | Odoo + российский вендор для фискальных модулей | 12-18 мес. | $200-400K |
| **Только POS (без бухгалтерии)** | UniCenta + кастомный модуль для 54-ФЗ | 6-12 мес. | $100-200K |
| **Полный ERP + POS + РФ-комплаенс** | ❌ Полноценной OSS-альтернативы **нет** | — | — |
| **Greenfield (новый проект)** | Django/FastAPI + Vue/React + PostgreSQL | 12-24 мес. | $200-500K |
| **🏆 Гибридный подход (рекомендуемый)** | 1С-ядро + веб-фронтенд через API | 4-8 мес. | $50-150K |

### Жёсткая правда
Для российской розницы с фискальной интеграцией **1С остаётся путём наименьшего сопротивления**. Стоимость полной миграции (≈$200K–$500K) обычно превышает 5–7 лет лицензирования 1С.

### Принцип разделения ответственности

| Компонент | Технология | За что отвечает | За что НЕ отвечает |
|-----------|-----------|-----------------|---------------------|
| **1С** | BSL + БПО | Учёт, проводки, фискализация, оборудование | UI, аналитика, UX |
| **API Gateway** | FastAPI (Python) | Auth (JWT), кеширование, rate limiting, логи | Бизнес-логика учёта |
| **POS UI** | React / Vue 3 + TypeScript | Интерфейс кассира, сканирование, UX | Проведение документов |
| **Дашборды** | React + Chart.js | Визуализация продаж, остатков | Расчёт данных |
| **Mobile** | PWA / React Native | Мобильный сканер, инвентаризация | — |

### Поэтапный план

#### Этап 0: Расширение HTTP API 1С (1–2 месяца)

| Endpoint | Method | Назначение | Статус |
|----------|--------|-----------|--------|
| `GET /api/goods` | GET | Каталог с фильтрами, пагинацией | 🔴 Нужно |
| `GET /api/goods/{id}` | GET | Карточка товара | 🔴 Нужно |
| `GET /api/goods/barcode/{code}` | GET | Поиск по штрихкоду | ✅ Есть |
| `GET /api/stock` | GET | Остатки по складам | 🔴 Нужно |
| `GET /api/prices` | GET | Цены по типам | 🟡 Опционально |
| `POST /api/checks` | POST | Создать чек | ✅ Есть |
| `GET /api/checks/{id}` | GET | Получить чек | 🔴 Нужно |
| `GET /api/shifts` | GET | Кассовые смены | ✅ Частично |
| `POST /api/shifts/open` | POST | Открыть смену | 🔴 Нужно |
| `POST /api/shifts/close` | POST | Закрыть смену | 🔴 Нужно |
| `GET /api/reports/sales` | GET | Продажи за период | 🔴 Нужно |
| `GET /api/reports/stock` | GET | Остатки товаров | 🔴 Нужно |
| `POST /api/auth/login` | POST | Авторизация → JWT | 🔴 Нужно |

#### Этап 1: API Gateway (1 месяц)

**Стек: FastAPI (Python)** — уже есть Python-экосистема в проекте.

Ценность:
- JWT-авторизация (вместо Basic Auth 1С)
- Кеширование каталога (Redis) — 1С не нагружается
- Rate limiting, CORS, HTTPS
- Swagger/OpenAPI — автодокументация
- Prometheus/Grafana мониторинг

#### Этап 2: Новый POS UI (2–3 месяца)

React + TypeScript + Tailwind CSS:
- `<Scanner/>` — камера + BarcodeDetector
- `<Cart/>` — корзина со скидками
- `<ProductSearch/>` — автодополнение
- `<ShiftPanel/>` — управление сменами
- `<PaymentDialog/>` — оплата
- `<CheckHistory/>` — история чеков

Offline-first: Service Worker + IndexedDB.

#### Этап 3: Аналитические дашборды (1–2 месяца)

| Дашборд | Источник данных |
|---------|----------------|
| Продажи в реальном времени | Регистр `Продажи` |
| Остатки на складах | Регистр `ОстаткиТоваров` |
| ABC/XYZ анализ | Агрегация `Продажи` |
| Взаиморасчёты | Регистр `Взаиморасчеты` |
| Кассовые смены | Документ `КассоваяСмена` |

#### Этап 4: Мобильное приложение (2–4 месяца, опционально)

PWA или React Native: инвентаризация, переоценка, мобильный кассир.

### Ключевые преимущества

1. **Нулевой риск** — 1С продолжает работать, веб подключается параллельно
2. **Инкрементальность** — каждый этап даёт ценность сам по себе
3. **Переиспользование** — 80% бизнес-логики остаётся в 1С
4. **Фискализация бесплатно** — БПО (100+ модулей) нетронут
5. **Современный UX** — React/Vue вместо управляемых форм
6. **Масштабируемость** — кеширование, CDN, горизонтальное масштабирование

## 6. Итог

Для российской розницы с фискальной интеграцией **гибридная архитектура** — оптимальный путь:
- 1С остаётся для учёта и фискализации
- Веб забирает UI, аналитику и мобильность
- Полная миграция возможна в будущем при изменении законодательства или появлении зрелых альтернатив с поддержкой ФФД
