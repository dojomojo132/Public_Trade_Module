## 1. Этап 2 — Ядро движка форм

### 1.1 `ptm-workspace/FRONT/src/lib/document/DocumentForm.svelte`

Главный компонент-движок. Принимает `config: DocumentConfig`, `id?: string`, `mode?: 'create' | 'edit' | 'view'`.

**Обязанности:**
- Состояние документа: `let doc = $state<AnyDoc>({ status: 'active', lines: [] })`.
- Загрузка существующего документа через `config.api.get` (или дефолтный `GET /api/documents/:id`).
- Создание `DocumentContext` (`id`, `mode`, `status`, `dirty`, `saving`, `goto`, `toast`).
- Поддержка snippets: `headerExtra(doc)`, `toolbarExtra(doc)`, `linesExtra(doc)`, `footerExtra(doc)`.
- Композиция: `<DocumentToolbar>` + `<DocumentHeader>` + `<DocumentLines>` + footer (totals).
- Глобальные хоткеи: `Ctrl+S`, `Ctrl+Enter` (= Сохранить и закрыть для MVP), `Esc` (с подтверждением dirty), `Ctrl+P` (печать).
- Заголовок страницы: `{config.title} №{doc.number ?? '...'} от {date} {dirty ? '*' : ''}`.
- Бейдж статуса в шапке (active — нет, excluded — жёлтый, deleted — серый).

**Slots/snippets API (Svelte 5):**

```svelte
<DocumentForm {config} {id}>
  {#snippet headerExtra(doc)}...{/snippet}
  {#snippet toolbarExtra(doc, ctx)}...{/snippet}
  {#snippet linesExtra(doc)}...{/snippet}
</DocumentForm>
```

### 1.2 `DocumentHeader.svelte`

- Рендерит `config.headerFields` в grid.
- Для каждого поля выбирает компонент по `kind`: `FieldString`, `FieldNumber`, `FieldDate`, `FieldEnum`, `FieldBool`, `FieldRef`, `FieldMultiline`.
- Поддерживает `tabOrder`, `visibleWhen`, `enabledWhen`, `span`.
- Tab/Shift+Tab — навигация. Tab после последнего поля → первая ячейка ТЧ.
- Enter в не-multiline поле = Tab.

### 1.3 `DocumentLines.svelte`

- Рендерит таблицу по `config.lineColumns`.
- **Grid-навигация (важно — посмотреть существующую логику в `invoices/new/+page.svelte` и вынести в `useGridNav.svelte.ts`):**
  - Стрелки ↑↓ — смена строки. ←→ — смена колонки.
  - Enter — войти в редактирование (или выйти + следующая ячейка).
  - F2 — войти в редактирование.
  - Esc — выйти из редактирования.
  - Ins — добавить строку ниже.
  - Del — удалить строку с подтверждением. Ctrl+Del — без подтверждения.
  - Цифры — войти в edit с начальным значением.
- `autoAddRow` (по умолчанию true): Enter в последней ячейке последней строки → новая строка.
- Колонки с `calc` — read-only, пересчитываются на каждое изменение `doc`.
- `onInput(line, value, doc)` — пользовательский хук.
- Поддержка `picker` для `ref`-колонок: если `picker.enabled` — в тулбаре ТЧ кнопка «Подбор».
- Подсветка активной ячейки: `ring-1 ring-brand-500`. Edit: `bg-slate-700 + ring`.

### 1.4 `DocumentToolbar.svelte`

Кнопки (с учётом `hideStandardCommands` и `commands`):
- **Сохранить** (`save`) — `Ctrl+S`. Видна когда `dirty || mode === 'create'`.
- **Исключить из движений** (`exclude`) — когда `status === 'active'`.
- **Вернуть в движения** (`restore`) — когда `status === 'excluded' || status === 'deleted'` (для deleted — это «Восстановить»).
- **Удалить** (`delete`) — переход в `deleted`. С подтверждением.
- **Копировать** (`copy`) — создать новый документ-черновик с теми же данными.
- **Печать** (`print`) — если `config.printComponent` указан. `Ctrl+P`.
- Кастомные команды из `config.commands` — после стандартных.

Перед операциями смены статуса/удаления — `config.validate(doc)` + `confirm()`.

### 1.5 Field-компоненты (`ptm-workspace/FRONT/src/lib/document/fields/`)

- `FieldString.svelte`, `FieldMultiline.svelte`, `FieldNumber.svelte` (с `format: integer|decimal|money|percent`), `FieldDate.svelte`, `FieldBool.svelte`, `FieldEnum.svelte`, `FieldRef.svelte`.
- Все принимают `{ field, value, onUpdate }` и эмитят изменения.
- `FieldRef` — переиспользовать существующий компонент справочника (или вынести из накладной).

### 1.6 Хуки (`ptm-workspace/FRONT/src/lib/document/`)

- `useGridNav.svelte.ts` — Svelte action / class для управления фокусом в таблице (взять из текущего `invoices/new`).
- `useDirty.svelte.ts` — следит за изменениями `doc` (deep watch через `$state.snapshot` + JSON-сравнение с начальным).
- `useHotkeys.svelte.ts` — регистрация Ctrl+S/Esc/Ctrl+P/Ctrl+Enter на уровне формы.

## 3. Этап 4 — Backend: статусы и движения

### 3.1 БД миграция

Добавить колонку `status` в `documents`:

```sql
ALTER TABLE documents
  ADD COLUMN status TEXT NOT NULL DEFAULT 'active'
  CHECK (status IN ('active', 'excluded', 'deleted'));
CREATE INDEX idx_documents_status ON documents(status) WHERE status != 'active';
```

Если в проекте уже есть `posted: bool` — мигрировать:
- `posted = true && deleted_at IS NULL` → `status = 'active'`
- `deleted_at IS NOT NULL` → `status = 'deleted'`
- Удалить старые колонки после успешной миграции (отдельной миграцией).

### 3.2 Таблицы регистров

```sql
CREATE TABLE register_stock_balance_movements (
  id BIGSERIAL PRIMARY KEY,
  document_id UUID NOT NULL REFERENCES documents(id),
  recorded_at TIMESTAMPTZ NOT NULL,
  warehouse_id UUID NOT NULL,
  product_id UUID NOT NULL,
  quantity NUMERIC(18, 3) NOT NULL,
  amount NUMERIC(18, 2) NOT NULL,
  sign SMALLINT NOT NULL CHECK (sign IN (-1, 1))
);
CREATE INDEX idx_rsbm_dims ON register_stock_balance_movements(warehouse_id, product_id, recorded_at);
CREATE INDEX idx_rsbm_doc ON register_stock_balance_movements(document_id);

CREATE TABLE register_stock_balance_snapshots (
  warehouse_id UUID NOT NULL,
  product_id UUID NOT NULL,
  period_start DATE NOT NULL,
  quantity NUMERIC(18, 3) NOT NULL,
  amount NUMERIC(18, 2) NOT NULL,
  PRIMARY KEY (warehouse_id, product_id, period_start)
);
```

### 3.3 Эндпоинты

В [ptm-workspace/ptm-server/src/main.rs](../ptm-workspace/ptm-server/src/main.rs) добавить:
- `POST /api/documents/:id/status` — body `{ "status": "excluded" }`. Меняет статус + пересчитывает движения и снапшоты.
- `POST /api/documents` и `PUT /api/documents/:id` — после сохранения **пересчитать movements** по конфигу (см. 3.4).

### 3.4 Загрузка конфигов в backend

- Создать папку `ptm-workspace/ptm-server/configs/documents/`.
- Скрипт `ptm-workspace/FRONT/scripts/export-configs.ts` (или vite plugin) — экспортирует `rules` из TS-конфигов в JSON. Поле `compute` пропускается (с warning).
- В Rust: на старте читаем все `*.json`, кэшируем в `HashMap<DocType, MovementsSpec>`.
- Hot-reload: SIGHUP или просто перезапуск dev-сервера.

### 3.5 Применение движений

Псевдокод:

```rust
fn apply_movements(doc: &Document, tx: &mut Transaction) -> Result<()> {
    // 1. Удалить все старые movements этого документа
    sqlx::query!("DELETE FROM register_stock_balance_movements WHERE document_id = $1", doc.id)
        .execute(&mut *tx).await?;

    // 2. Если status != 'active' — не пишем новых
    if doc.status != "active" { return Ok(()); }

    // 3. Прогнать rules из конфига
    let spec = configs.get(&doc.doc_type).ok_or(...)?;
    let movements = compute_movements_from_rules(doc, &spec.rules)?;

    // 4. Вставить
    for m in movements { insert_movement(&mut *tx, doc.id, m).await?; }

    // 5. Пересчитать снапшоты затронутых разрезов от даты документа вперёд
    recalc_snapshots(&mut *tx, &spec.snapshot, &affected_dimensions, doc.recorded_at).await?;

    Ok(())
}
```
