## 5. КЛЮЧЕВЫЕ ВЫВОДЫ

### 5.1 Главный разрыв — бизнес-уровневые запросы

Текущие `get_register_data` и `execute_query` дают доступ к данным, но агент должен знать внутреннюю структуру регистров (измерения, ресурсы, суффиксы `Остаток`/`Оборот`). 

**6 инструментов P0** (`find_product`, `get_product_info`, `get_current_prices`, `check_stock`, `get_supplier_debts`, `get_default_setting`) закрывают **80% типичных вопросов** "покажи товар / цену / остаток / долг" одним вызовом.

### 5.2 Настройки ≠ Константы

Регистр `НастройкиПоУмолчанию` — Key-Value с сериализацией через `ЗначениеВСтрокуВнутр`. Текущие `get_constant_value` / `set_constant_value` **НЕ работают** с ним. Нужны отдельные `get_default_setting` / `set_default_setting` / `list_default_settings`.

### 5.3 ТЖ — ~~слепое пятно MCP~~ → РЕШЕНО ✅

`get_event_log` читает **Журнал регистрации (ЖР)**. ~~Runtime-ошибки (EXCP, SDBL, CALL) попадали в Технологический журнал (ТЖ), недоступный через MCP.~~

**РЕШЕНО (26.02.2026):** Инструмент `get_tech_journal` (action=Check/Setup/Stop/Status) читает `.log`-файлы ТЖ через `КопироватьФайл()` + BSL-парсинг XML. Safe mode отключён на расширении — доступ к файловой системе работает. Оба источника ошибок (ЖР + ТЖ) теперь доступны через MCP без PowerShell.

### 5.4 Кассовые смены — бизнес-критичный разрыв

Управление сменами (open/close/status) — ядро POS-системы, но полностью отсутствует в MCP. `manage_cash_shift` + `get_shift_summary` — P1 после P0.

### 5.5 ~30 скриптов — мусор

Из 52 Python-скриптов ~30 одноразовые (привязаны к конкретным коммитам, объектам, бэкапам). Рекомендуется перенести в `scripts/archive/`.

### 5.6 Реализация P0 — минимум нового кода

Инструменты 1, 2, 3, 6 из P0 реализуются **вызовом готовых BSL-функций** из `ОбщегоНазначения` и `НастройкиПоУмолчанию`. Для 4 и 5 нужен простой запрос к регистрам накопления.
