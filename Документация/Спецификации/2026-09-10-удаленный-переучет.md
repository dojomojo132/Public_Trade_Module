# Удалённый переучёт через кеш-сервер

**Дата:** 2026-09-10  
**Статус:** к реализации  
**ADR:** `Документация/API/ADR-002-remote-inventory-cache.md`  
**Итерация:** параллельный контур к LAN-переучёту. LAN `/hs/mobile/inv/*` не меняем.

## 1. Цель

Телефон считает товар **не в 1С**, а на удалённом сервере (кеш штрихкодов и фактов).  
1С получает черновик `ИнвентаризацияТоваров` периодически через PTM_API.  
Пока туннель до 1С мёртв, скан и запись количества продолжают работать.

## 2. Контуры

| Контур | Где | Запись скана |
|--------|-----|----------------|
| LAN (существующий) | `/hs/mobile/inv/*` в расширении Analytics | сразу в ТЧ документа |
| Remote (этот) | `remote_inventory/` на VPS | SQLite-кеш, затем POST/PUT `/hs/ptm/v1/inventories` |

Оба контура сходятся в одном документе `ИнвентаризацияТоваров`. Сведение нескольких черновиков — команда в 1С, не с телефона.

## 3. Поведение на телефоне

Порядок: вход → склад (из кеша) → список черновиков + **Создать** → документ.

**Скан**

- Поиск только в кеше `barcodes` middleware.
- Нет ШК → ошибка, строку не создавать.
- Скан **не** +1.
- Нет строки → создать (факт 0) → ввод количества.
- Строка есть → подсветить → число **заменяет** факт.
- Повторный скан той же позиции — снова замена.

**Запись** — сразу в кеш сессии. Не в 1С.

**Проведение с телефона нет.**

**Два телефона, один черновик** — одна строка за запрос (блокировка `session_id + product_id`).

## 4. Синхронизация с 1С

| Поток | Период | Источник |
|-------|--------|----------|
| Pull каталога | 15 мин + кнопка | `GET /barcodes`, `GET /warehouses`, `GET /products` |
| Push черновиков | 2–5 мин если dirty + `POST /inv/sync` | `POST` / `PUT /inventories` |

Идемпотентность: `externalId` сессии = реквизит `ВнешнийИд` документа. Повторный POST не создаёт второй документ.

Push пишет **непроведённый** документ. Неизвестный `productId` → 400, сессия `error`, факты в кеше сохраняются.

Статусы сессии: `draft` → `syncing` → `synced` | `error`.

## 5. Auth

- Телефон → middleware: HTTPS + cookie-сессия (свои учётки зала).
- Middleware → 1С: `X-Api-Key` (константа `Апи_Ключ`). Телефон 1С не видит.

## 6. API телефона (middleware)

База: origin сервиса `remote_inventory`.

| Метод | Путь | Смысл |
|-------|------|--------|
| POST | `/login` | учётка middleware |
| GET | `/inv/warehouses` | склады из кеша |
| GET | `/inv/docs?warehouse=` | черновики склада |
| POST | `/inv/docs` | `{warehouse, comment, author}` |
| GET | `/inv/doc?id=` | шапка + строки |
| DELETE | `/inv/docs?id=` | пометка удаления в кеше |
| POST | `/inv/scan` | `{id, barcode}` → `{line, name, qty, created}` |
| POST | `/inv/qty` | `{id, line, qty}` замена |
| POST | `/inv/sync` | ручной push + опциональный pull |
| GET | `/inv/status` | доступность 1С, время последнего pull/push |

Ошибки телефона: `{success:false, error}` + HTTP 400/401/404/409 (как LAN).  
Это **не** envelope PTM_API; PTM_API остаётся `ErrorResponse`.

## 7. Write в 1С

Контракт: `openapi-v1.yaml` — `POST /inventories`, `PUT /inventories/{id}`.

Тело: `externalId`, `warehouseId`, `comment`, `authorName`, `items[{productId, barcode, qty}]`.

## 8. Вне скоупа

- Правки `Анл_МобильнаяКасса` и LAN `/inv/*`
- Проведение и «заполнить по остаткам» с телефона
- Создание номенклатуры с телефона
- Live-обновление чужого экрана
- Delta-sync штрихкодов

## 9. Приёмка

1. Скан неизвестного ШК — ошибка, без строки.
2. Повторный скан — замена qty, не +1.
3. 1С выключена — скан и qty живы; статус «1С недоступна».
4. После появления туннеля — непроведённый `ИнвентаризацияТоваров` с фактами, `ВнешнийИд` = uuid сессии.
5. Повторный sync — тот же документ, не дубль.
6. LAN-касса / LAN-переучёт (если есть) без регрессии.
