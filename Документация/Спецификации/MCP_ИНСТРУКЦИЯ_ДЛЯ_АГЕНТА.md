## 1. ОБЩИЕ ПРАВИЛА РАБОТЫ С MCP

### 1.1 Приоритет вызова

```
ПЕРЕД написанием кода агент ОБЯЗАН использовать MCP-инструменты в таком порядке:

1. list_metadata_objects → убедиться, что объект существует
2. get_metadata_structure → получить реквизиты, ТЧ, измерения
3. list_enum_values → проверить имена значений перечислений (если код ссылается на перечисление)
4. get_object_module → прочитать ТЕКУЩИЙ модуль из живой ИБ (не файл на диске!)
5. get_register_data → проверить текущие данные в регистрах (если задача затрагивает данные)
```

### 1.2 Именование MCP-инструментов в VS Code

Все MCP-инструменты проекта получают префикс `mcp_mcp_1c_torgov_` при вызове из VS Code:

### 2.2 Правила использования `execute_query`

```
✅ ИСПОЛЬЗОВАТЬ для:
  - Проверки остатков: ВЫБРАТЬ * ИЗ РегистрНакопления.ОстаткиТоваров.Остатки()
  - Проверки движений: ВЫБРАТЬ * ИЗ РегистрНакопления.Продажи ГДЕ Регистратор = &Док
  - Анализа данных: ВЫБРАТЬ КОЛИЧЕСТВО(*) ИЗ Справочник.Номенклатура
  - Проверки цен: ВЫБРАТЬ * ИЗ РегистрСведений.ЦеныНоменклатуры.СрезПоследних()

❌ ЗАПРЕЩЕНО:
  - Выполнять модифицирующие запросы (UPDATE/INSERT через execute_query)
  - Использовать params для передачи ссылок без правильного формата
  - Запрашивать более 100 строк без явной необходимости (maxRows)
```

### 2.3 Правила использования `get_register_data`

```
Параметр mode:
  - "Balance"    → РегистрНакопления.Имя.Остатки()     (только для регистров остатков)
  - "Turnovers"  → РегистрНакопления.Имя.Обороты()     (для любых регистров накопления)
  - "SliceLast"  → РегистрСведений.Имя.СрезПоследних() (для периодических регистров сведений)
  - "All"        → все записи без агрегации              (для любых регистров)

Регистры PTM:
  - AccumulationRegisters.ОстаткиТоваров       → Balance, Turnovers, All
  - AccumulationRegisters.Взаиморасчеты         → Balance, Turnovers, All
  - AccumulationRegisters.ДенежныеСредства      → Balance, Turnovers, All
  - AccumulationRegisters.Продажи               → Turnovers, All
  - AccumulationRegisters.ПродажиПоДисконтнымКартам → Turnovers, All
  - InformationRegisters.ЦеныНоменклатуры       → SliceLast, All
  - InformationRegisters.Штрихкоды              → All
  - InformationRegisters.НастройкиПоУмолчанию   → All
```

### 2.4 Правила использования `get_document_movements`

```
Документы PTM и их регистры:
  - ЧекККМ → ОстаткиТоваров, Продажи, ДенежныеСредства, ПродажиПоДисконтнымКартам, Взаиморасчеты
  - ПриходТовара → ОстаткиТоваров, Взаиморасчеты
  - СписаниеТовара → ОстаткиТоваров
  - ИнвентаризацияТоваров → ОстаткиТоваров
  - Переоценка → ОстаткиТоваров (через создание документов)
  - ВозвратТовараОтПокупателя → ОстаткиТоваров, Продажи, ДенежныеСредства
  - ПриходныйКассовыйОрдер → ДенежныеСредства, Взаиморасчеты
  - РасходныйКассовыйОрдер → ДенежныеСредства, Взаиморасчеты

Workflow проверки проведения:
  1. get_document_movements(documentType, documentNumber) → видим движения
  2. Если движений нет → проверить ОбработкаПроведения в ObjectModule.bsl
  3. Если движения неверные → проверить RegisterRecords в XML документа
```

### 2.5 Правила использования `list_enum_values`

```
Перечисления PTM (часто используемые):
  - СтавкиНДС → БезНДС, НДС20, НДС10, ...
  - ВидыОплаты → Наличные, Безналичные, ...
  - СтатусыЧекаККМ → Оформлен, Аннулирован, ...
  - СтатусыКассовойСмены → Открыта, Закрыта, ...
  - ЕдиницыИзмерения → Штука, Килограмм, Литр, ...
  - ВидыОперацийФискальногоЧека → Приход, Расход, ВозвратПрихода, ВозвратРасхода

❌ ЗАПРЕЩЕНО: угадывать имена значений перечислений
✅ ОБЯЗАТЕЛЬНО: вызвать list_enum_values ПЕРЕД использованием значения в BSL-коде
```

## 3. ФАЗА 2: Модули и код

### 3.1 Правила использования `get_object_module`

```
✅ ИСПОЛЬЗОВАТЬ когда:
  - Нужно прочитать текущий код из ИБ (может отличаться от файла на диске!)
  - Нужно прочитать код расширения БПО (его нет на диске)
  - Нужно проверить, какой код реально выполняется

Параметр moduleType:
  - "ObjectModule"    → Модуль объекта (обработка проведения и др.)
  - "ManagerModule"   → Модуль менеджера
  - "FormModule"      → Модуль формы (требует formName)
  - "RecordSetModule" → Модуль набора записей регистра

Частые вызовы:
  get_object_module(metaType="Documents", name="ЧекККМ", moduleType="ObjectModule")
  get_object_module(metaType="Documents", name="ЧекККМ", moduleType="FormModule", formName="ФормаДокумента")
  get_object_module(metaType="CommonModules", name="ОбщийМодуль")
```

### 3.2 Правила использования `execute_code`

```
⚠️ ОСТОРОЖНО: Этот инструмент выполняет ПРОИЗВОЛЬНЫЙ код на сервере 1С!

✅ ИСПОЛЬЗОВАТЬ для:
  - Проверки формул и вычислений
  - Быстрого тестирования фрагментов BSL
  - Получения данных, которые сложно получить запросом
  - Диагностики проблем

❌ ЗАПРЕЩЕНО (в safeMode=true):
  - Модификация данных (запись документов, справочников)
  - Работа с файловой системой
  - COM-объекты

Правила кода:
  - Результат ОБЯЗАТЕЛЬНО записывать в переменную Результат
  - Использовать safeMode=true по умолчанию
  - safeMode=false — только с явного разрешения пользователя

Примеры:
  execute_code(code="Результат = ТекущаяДатаСеанса()")
  execute_code(code="Результат = Метаданные.Документы.ЧекККМ.Движения.Количество()")
  execute_code(code="Результат = Строка(ПредопределённоеЗначение(""Перечисление.СтавкиНДС.БезНДС""))")
```

## 4. ФАЗА 2: Администрирование

### 4.1 Правила использования `get_users_list`

```
✅ ИСПОЛЬЗОВАТЬ:
  - ПОСЛЕ каждого деплоя (проверка, что пользователи на месте)
  - При подозрении на потерю данных
  - При настройке ролей и прав

КРИТИЧНО: Если после деплоя количество пользователей = 0, это КРИТИЧЕСКАЯ ОШИБКА.
  → Немедленный откат: deploy-config.ps1 -Action Rollback
  → Записать в КРИТИЧЕСКИЕ_ОШИБКИ.md
```

### 4.2 Правила использования `get_event_log`

```
✅ ИСПОЛЬЗОВАТЬ ВМЕСТО monitor-errors.ps1 для быстрой проверки:
  get_event_log(level="Error", lastMinutes=5)

Уровни:
  - "Error"       → Ошибки (runtime-исключения)
  - "Warning"     → Предупреждения
  - "Information" → Информационные сообщения

Workflow мониторинга (УЛУЧШЕННЫЙ):
  ЭТАП 9 (мониторинг): 
    ВАРИАНТ A: get_event_log(level="Error", lastMinutes=5)     ← MCP (быстрее)
    ВАРИАНТ Б: monitor-errors.ps1 -Action Check -LastMinutes 5 ← PowerShell (ТЖ + ЖР)
    
  Рекомендация: Использовать ВАРИАНТ A для быстрой проверки.
  Если нужен полный анализ (включая ТЖ) — ВАРИАНТ Б.
```

## 5. СВОДКА: КАКОЙ ИНСТРУМЕНТ КОГДА ИСПОЛЬЗОВАТЬ

### 5.1 Сценарий: Написание кода проведения документа

```
1. list_metadata_objects(metaType="Documents")              → найти документ
2. get_metadata_structure(metaType="Documents", name="X")   → реквизиты, ТЧ
3. list_enum_values(name="<перечисление>")                  → имена значений
4. get_register_data(registerType="AccumulationRegisters",   → текущие данные
                     name="ОстаткиТоваров", mode="Balance")
5. [НАПИСАТЬ КОД]
6. [ДЕПЛОЙ]
7. get_document_movements(documentType="X", documentNumber="001") → проверка движений
8. get_register_data(..., mode="Balance")                    → проверка остатков после проведения
```

### 5.2 Сценарий: Рефакторинг существующего объекта

```
1. get_metadata_structure(metaType="...", name="X")          → структура
2. get_object_module(metaType="...", name="X")               → текущий код из ИБ
3. find_references(objectRef="Тип.X")                        → где используется
4. [НАПИСАТЬ ИЗМЕНЕНИЯ]
5. [ДЕПЛОЙ]
6. execute_query(queryText="ВЫБРАТЬ ...")                     → проверка данных
```

### 5.3 Сценарий: Диагностика ошибки в работающей системе

```
1. get_event_log(level="Error", lastMinutes=30)              → ошибки из ЖР
2. get_object_module(metaType="...", name="...",              → код, который падает
                     moduleType="ObjectModule")
3. execute_query(queryText="ВЫБРАТЬ...")                      → состояние данных
4. execute_code(code="Результат = ...")                       → тестирование гипотезы
5. [ИСПРАВИТЬ]
6. [ДЕПЛОЙ]
7. get_event_log(level="Error", lastMinutes=5)               → проверка, что ошибка ушла
```

### 5.4 Сценарий: Проверка после деплоя

```
1. get_users_list()                                          → пользователи на месте?
2. get_event_log(level="Error", lastMinutes=5)               → нет ли новых ошибок?
3. execute_query(queryText="ВЫБРАТЬ КОЛИЧЕСТВО(*) ИЗ         → данные на месте?
   Справочник.Номенклатура")
```

### 4.4 MCP — неправильное использование

| ❌ ОШИБКА | ✅ ПРАВИЛЬНО | Комментарий |
|-----------|-------------|-------------|
| Угадывать значения перечислений | Вызвать `list_enum_values` | Имена могут отличаться от синонимов |
