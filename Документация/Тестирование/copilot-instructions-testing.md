## 13. ТЕСТИРОВАНИЕ

### 13.1 Инструменты тестирования

| Инструмент | Уровень | Назначение | Статус |
|-----------|---------|------------|--------|
| `_ptm_analyze.py` | 0а — Анализ кода | Проверка по СписокИсправлений | Работает |
| BSL Language Server | 0б — Статический анализ | Диагностики кода (.bsl) | Работает |
| YAxUnit | 1 — Unit-тесты | Проведение, логика, валидация | Установка |
| YAxUnit (дымовые) | 2 — Дымовые тесты | Открытие форм | Установка |
| Vanessa Automation | 3 — Сценарные тесты | Полные бизнес-циклы | Будущее |

### 13.2 Конфигурация

| Файл | Путь | Назначение |
|------|------|------------|
| Python-анализатор | `_ptm_analyze.py` | Проверка BSL по паттернам СписокИсправлений |
| Конфиг BSL LS | `.bsl-language-server.json` | Диагностики (DeprecatedCurrentDate, UsingModalWindows и др.) |
| Скрипт тестов | `Документация/Тестирование/run-tests.ps1` | Запуск всех уровней тестов |
| Шаблоны тестов | `Документация/Тестирование/Шаблоны/*.bsl` | BSL-код тестовых модулей YAxUnit |
| Сценарии | `Документация/Тестирование/Сценарии/*.feature` | Gherkin-сценарии (Vanessa) |
| Алгоритм | `Документация/Тестирование/АЛГОРИТМ_ТЕСТИРОВАНИЯ.md` | Полное описание workflow |

### 13.3 Интеграция в диалоги (УЖЕ ДОБАВЛЕНО в copilot-instructions.md)

Тестирование доступно через **3 точки входа** в диалогах:

```
┌─────────────────────────────────────────────────────────────────┐
│  ДИАЛОГ 3 (стартовый)          ДИАЛОГ 1 (после мониторинга)    │
│  ┌─────────────────────┐       ┌─────────────────────────┐     │
│  │ 1. Мониторинг       │       │ 1. Всё работает         │     │
│  │ 2. ★ Протестировать │       │ 2. Есть ошибка          │     │
│  │ 3. Новый запрос     │       │ 3. ★ Протестировать     │     │
│  └────────┬────────────┘       │ 4. Нужно больше времени │     │
│           │                    └────────┬────────────────┘     │
│           └──────────┐  ┌──────────────┘                       │
│                      ▼  ▼                                      │
│              ┌──────────────────┐                               │
│              │   ЭТАП 13: ТЕСТЫ │                               │
│              │ a) BSL-анализ     │                               │
│              │ b) _ptm_analyze   │                               │
│              │ c) YAxUnit        │                               │
│              └────────┬─────────┘                               │
│                       │ ↻ ЦИКЛ: ошибки → фикс → деплой         │
│                       ▼                                         │
│              ЭТАП 9: Мониторинг (возврат в основной цикл)       │
└─────────────────────────────────────────────────────────────────┘
```

### 13.4 Порядок выполнения ЭТАП 13

При выборе "Протестировать" в любом диалоге агент выполняет **последовательно**:

| Шаг | Действие | Команда |
|-----|---------|---------|
| a | **Статический анализ BSL** | `run-tests.ps1 -Action BslAnalysis` |
| b | **Анализ по СписокИсправлений** | `python _ptm_analyze.py` |
| c | **Unit-тесты YAxUnit** (если установлен) | `run-tests.ps1 -Action YAxUnit` |

**Цикл исправлений:**
```
Тест найдёт проблемы? → Исправить BSL/XML → deploy-config.ps1 -Action Full → Повторить тесты
                        ↻ ЦИКЛ пока все тесты не будут пройдены
                        → Все тесты OK → НАЗАД К ЭТАПУ 9 (мониторинг)
```

### 13.5 Запуск тестов (команды)

```powershell
# Статический анализ (ДО деплоя)
$script = Get-ChildItem -Path "D:\Git\Public_Trade_Module" -Recurse -Filter "run-tests.ps1" | Select-Object -First 1
powershell -ExecutionPolicy Bypass -File $script.FullName -Action BslAnalysis

# Анализ по СписокИсправлений (Python)
python "D:\Git\Public_Trade_Module\_ptm_analyze.py"

# Unit-тесты (ПОСЛЕ деплоя)
powershell -ExecutionPolicy Bypass -File $script.FullName -Action YAxUnit

# Все тесты
powershell -ExecutionPolicy Bypass -File $script.FullName -Action Full

# Проверка окружения
powershell -ExecutionPolicy Bypass -File $script.FullName -Action Status
```

### 13.6 Правила для агента (при написании тестов)

| ❌ ЗАПРЕЩЕНО | ✅ ПРАВИЛЬНО |
|-------------|-------------|
| Тест без имени (`Тест1`) | Действие+Ожидание (`ПроведениеСоздаётДвижения`) |
| Тест без утверждений | Минимум 1 `ЮТест.ОжидаетЧто(...)` |
| Модификация рабочих данных | Использовать `ЮТест.Данные()` (с откатом) |
| Тест зависит от порядка | Каждый тест независим |
| `Новая Структура` в тестах | `Новый Структура` (правило BSL) |

### 13.7 Шаблон тестового модуля (копировать)

```bsl
// Общий модуль: ОМ_ТестыXXX (Сервер, ВызовСервера)
#Область ПрограммныйИнтерфейс
Процедура ИсполняемыеСценарии() Экспорт
    ЮТТесты
        .ДобавитьТестовыйНабор("Описание набора")
            .ДобавитьТест("ДействиеПроизводитОжидание")
    ;
КонецПроцедуры
#КонецОбласти

#Область Тесты
Процедура ДействиеПроизводитОжидание() Экспорт
    // Arrange — подготовка
    Данные = ПодготовитьДанные();
    // Act — действие
    Результат = ВызватьТестируемыйМетод(Данные);
    // Assert — проверка
    ЮТест.ОжидаетЧто(Результат).Равно(ОжидаемоеЗначение);
КонецПроцедуры
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
Функция ПодготовитьДанные()
    // Создание тестовых данных через ЮТест.Данные()
КонецФункции
#КонецОбласти
```
