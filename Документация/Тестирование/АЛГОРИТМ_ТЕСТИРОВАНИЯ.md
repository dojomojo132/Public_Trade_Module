## 3. Уровни тестирования

### Уровень 0: Статический анализ (BSL Language Server)

**Когда:** ПЕРЕД деплоем (сразу после написания кода)  
**Что проверяет:**
- `ТекущаяДата()` → `ТекущаяДатаСеанса()` (DeprecatedCurrentDate)
- Модальные вызовы: `ПоказатьВопрос()`, `Предупреждение()` (UsingModalWindows)
- Устаревшие функции: `Найти()` → `СтрНайти()` (DeprecatedFind)
- `Сообщить()` без привязки (DeprecatedMessage)
- Когнитивная сложность > 20 (CognitiveComplexity)
- Размер метода > 200 строк (MethodSize)
- Закомментированный код (CommentedCode)

**Конфигурация:** `.bsl-language-server.json` в корне проекта  
**Результат:** 0 ошибок = OK, иначе → исправить до деплоя

**Запуск:**
```powershell
$script = Get-ChildItem -Path "D:\Git\Public_Trade_Module" -Recurse -Filter "run-tests.ps1" | Select-Object -First 1
powershell -ExecutionPolicy Bypass -File $script.FullName -Action BslAnalysis
```

### Уровень 1: Модульные тесты (YAxUnit)

**Когда:** ПОСЛЕ успешного деплоя  
**Что проверяет:**
- Проведение документов → движения по регистрам
- Валидация данных (пустые поля, нулевые суммы)
- Расчёты (суммы, скидки, взаиморасчёты)
- Бизнес-правила (аннулирование, статусы)

**Расширение:** ТестыPTM (содержит модули тестов)  
**Фреймворк:** YAxUnit (cfe-расширение в ИБ)

**Запуск:**
```powershell
$script = Get-ChildItem -Path "D:\Git\Public_Trade_Module" -Recurse -Filter "run-tests.ps1" | Select-Object -First 1
powershell -ExecutionPolicy Bypass -File $script.FullName -Action YAxUnit
```

### Уровень 2: Дымовые тесты

**Когда:** ПОСЛЕ успешного деплоя  
**Что проверяет:**
- Все формы PTM открываются без ошибок
- Формы справочников, документов, обработок

**Тип:** Часть YAxUnit (встроенный генератор или модуль `ОМ_ДымовыеТестыPTM`)

### Уровень 3: Сценарные тесты (Vanessa Automation) [БУДУЩЕЕ]

**Когда:** После стабилизации уровней 0-2  
**Что проверяет:**
- Полный цикл кассовой смены (открытие → чеки → закрытие)
- Сценарий прихода товара с переоценкой
- Возвраты товара

## 6. Быстрый старт (пошаговая инструкция)

### Шаг 1: BSL Language Server (работает сразу!)

`.bsl-language-server.json` уже создан в корне проекта. VS Code подхватит его автоматически, и вы увидите диагностики (жёлтые/красные подчёркивания) прямо в редакторе.

**Проверить:** Откройте любой `.bsl` файл — должны появиться предупреждения о `ТекущаяДата()` и других проблемах.

### Шаг 2: Установка YAxUnit

```
1. Скачать последний релиз yaxunit.cfe:
   https://github.com/bia-technologies/yaxunit/releases

2. Открыть конфигуратор → Конфигурация → Расширения конфигурации

3. Добавить из файла → выбрать yaxunit.cfe

4. Снять галочки:
   ☐ Безопасный режим
   ☐ Защита от опасных действий

5. Обновить конфигурацию БД
```

### Шаг 3: Создание расширения с тестами

```
1. Конфигуратор → Конфигурация → Расширения → Создать

2. Имя: ТестыPTM
   Назначение: Дополнение

3. Добавить общие модули:
   - ОМ_ТестыЧекККМ (Сервер, ВызовСервера)
   - ОМ_ТестыПриходТовара (Сервер, ВызовСервера)
   - ОМ_ДымовыеТестыPTM (Сервер, ВызовСервера)

4. Скопировать код из Документация/Тестирование/Шаблоны/*.bsl

5. Обновить конфигурацию БД
```

### Шаг 4: Запуск тестов

```powershell
# Проверить окружение:
$script = Get-ChildItem -Path "D:\Git\Public_Trade_Module" -Recurse -Filter "run-tests.ps1" | Select-Object -First 1
powershell -ExecutionPolicy Bypass -File $script.FullName -Action Status

# Запустить все тесты:
powershell -ExecutionPolicy Bypass -File $script.FullName -Action Full
```

## 8. Правила написания тестов (для Copilot Agent)

### 8.1 Когда писать тесты

| Ситуация | Нужен тест? | Тип теста |
|----------|-------------|-----------|
| Новый документ с проведением | **Да** | Unit (движения по регистрам) |
| Новая форма | **Да** | Дымовой (открытие формы) |
| Новый расчёт/алгоритм | **Да** | Unit (входы → выходы) |
| Баг-фикс | **Да** | Регрессионный (воспроизвести баг → тест) |
| Изменение реквизита | Нет (если нет логики) | — |
| Рефакторинг | НЕТ (тесты уже есть) | Существующие защищают |

### 8.2 Структура тестового модуля

```bsl
// Общий модуль: ОМ_ТестыXXX (Сервер, ВызовСервера)

#Область ПрограммныйИнтерфейс

Процедура ИсполняемыеСценарии() Экспорт
    ЮТТесты
        .ДобавитьТестовыйНабор("Название набора")
            .ДобавитьТест("ИмяТеста")
    ;
КонецПроцедуры

#КонецОбласти

#Область Тесты

Процедура ИмяТеста() Экспорт
    // 1. Подготовка (Arrange)
    // 2. Действие (Act)
    // 3. Проверка (Assert)
КонецПроцедуры

#КонецОбласти

#Область СлужебныеПроцедурыИФункции
    // Вспомогательные функции
#КонецОбласти
```

### 8.3 Именование тестов

```
✅ ПроведениеСоздаётДвиженияОстатков     — Действие + Ожидание
✅ ЧекБезТоваровНеПроводится             — Условие + Ожидание
✅ СуммаДокументаРавнаСуммеТоваров       — Факт для проверки
❌ Тест1                                  — бессмысленно
❌ ПроверкаЧека                           — не ясно что проверяется
```

### 8.4 Утверждения YAxUnit (шпаргалка)

```bsl
// Простые проверки
ЮТест.ОжидаетЧто(Значение).Равно(5);
ЮТест.ОжидаетЧто(Значение).НеРавно(0);
ЮТест.ОжидаетЧто(Значение).Больше(0);
ЮТест.ОжидаетЧто(Значение).Заполнено();
ЮТест.ОжидаетЧто(Значение).НеЗаполнено();
ЮТест.ОжидаетЧто(Значение).ИмеетТип("Строка");

// Коллекции
ЮТест.ОжидаетЧто(Массив).ИмеетДлину(3);
ЮТест.ОжидаетЧто(Массив).Содержит("элемент");

// Регистры
Записи = ЮТЗапросы.ЗаписиРегистра("РегистрНакопления.ОстаткиТоваров", Ссылка);
ЮТест.ОжидаетЧто(Записи).Заполнено();

// Исключения
ЮТест.ОжидаетЧто(
    ЮТест.ВыполнитьСПерехватомИсключения("Метод", Модуль, Параметр))
    .Заполнено();

// Пропуск теста
ЮТест.Пропустить("Причина пропуска");

// Провал теста вручную
ЮТест.Провалить("Описание проблемы");
```

## 10. Часто задаваемые вопросы

**Q: Тесты модифицируют рабочую базу?**  
A: Нет. YAxUnit использует транзакции с откатом — тестовые данные удаляются после каждого теста. Рекомендуется использовать отдельную тестовую ИБ (`-TestBasePath`).

**Q: Можно ли запускать тесты без YAxUnit?**  
A: Да. BSL Language Server (Уровень 0) работает без 1С. Это самый простой и полезный шаг — ловит устаревшие конструкции, модальные вызовы, длинные методы.

**Q: Что если тесты ломаются после каждого деплоя?**  
A: Это нормально в начале. Сначала стабилизируем дымовые тесты (открытие форм), затем unit-тесты. Хрупкие тесты → доработать или пометить `ЮТест.Пропустить()`.

**Q: Нужна ли отдельная тестовая ИБ?**  
A: Рекомендуется, но не обязательно. YAxUnit откатывает тестовые данные. Отдельная ИБ — дополнительная страховка.
