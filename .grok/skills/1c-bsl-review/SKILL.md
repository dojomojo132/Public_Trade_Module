# Ревью BSL-кода (1С 8.3.27)

## Когда использовать

- Code review модулей BSL
- Проверка перед деплоем
- Валидация клиент-серверного контекста

## Процедура

### 1. Автоматические проверки

```
onec-mcp → get_errors  (все изменённые .bsl)
dev-mcp → dev_validate   (если менялся XML)
```

### 2. Негативный словарь

| ❌ | ✅ |
|----|-----|
| `Новая Структура` | `Новый Структура` |
| `ЗначениеВСтроку()` | `ЗначениеВСтрокуВнутр()` |
| `ТекущаяДата()` | `ТекущаяДатаСеанса()` |
| `Вопрос()` | `ВопросАсинх()` |
| `Сообщить()` | `СообщениеПользователю` |
| `РольДоступна()` | `ПравоДоступа()` |

Полный список: skill `1c-anti-patterns`, `.github/instructions/bsl.instructions.md`.

### 3. Структура

- [ ] Директива на отдельной строке у каждого метода
- [ ] Код только в `#Область`
- [ ] UTF-8 BOM + CRLF у новых файлов

### 4. Запросы и транзакции

- [ ] Псевдонимы, параметры, нет запросов в циклах
- [ ] `НачатьТранзакцию` → `Попытка` → `Зафиксировать` / `Отменить` + `ВызватьИсключение`

### 5. Безопасность

- [ ] Нет `Выполнить`/`Вычислить` с переменными
- [ ] Нет привилегированного режима без обоснования

## Формат вывода

```markdown
## Результат ревью BSL

### Критические (блокируют деплой)
- файл:строка — проблема

### Важные
- файл:строка — проблема

### Замечания
- файл:строка — замечание
```

Критические должны быть исправлены до деплоя.
